Proofs: Design Paradigms

This page proves the claims of the chapter: the formulas used to analyze divide and conquer, the correctness and cost of several divide and conquer algorithms, the optimality of the greedy algorithms that the lessons call optimal, and the recurrences of dynamic programming. The general techniques (induction, recursion trees, geometric series) are in the Mathematical Background chapter.

The division formula​

Claim. If T(n)=a T(n/b)+c nkT(n) = a \, T(n/b) + c \, n^kT(n)=aT(n/b)+cnk for nnn larger than the base case, with constants a≥1a \ge 1a≥1, b>1b \gt 1b>1, k≥0k \ge 0k≥0 and c>0c \gt 0c>0, then

T(n)∈{O(nk)if a<bkO(nklog⁡n)if a=bkO(nlog⁡ba)if a>bkT(n) \in \begin{cases} O(n^k) & \text{if } a \lt b^k \\ O(n^k \log n) & \text{if } a = b^k \\ O(n^{\log_b a}) & \text{if } a \gt b^k \end{cases}T(n)∈⎩⎨⎧​O(nk)O(nklogn)O(nlogb​a)​if a<bkif a=bkif a>bk​

  • If r<1r \lt 1r<1 (a<bka \lt b^ka<bk), the sum is at most 11−r\frac{1}{1 - r}1−r1​, a constant: T(n)∈O(nk)T(n) \in O(n^k)T(n)∈O(nk). The root dominates.

The subtraction formula​

Claim. If T(n)=a T(n−b)+c nkT(n) = a \, T(n - b) + c \, n^kT(n)=aT(n−b)+cnk for nnn larger than the base case, with b≥1b \ge 1b≥1, then T(n)∈O(nk+1)T(n) \in O(n^{k+1})T(n)∈O(nk+1) if a=1a = 1a=1, and T(n)∈O(an/b)T(n) \in O(a^{n/b})T(n)∈O(an/b) if a>1a \gt 1a>1.

Karatsuba's identity​

Karatsuba's algorithm multiplies two numbers of nnn digits by splitting each one in halves, x=x1B+x0x = x_1 B + x_0x=x1​B+x0​ and y=y1B+y0y = y_1 B + y_0y=y1​B+y0​, where BBB is a power of the base with n/2n/2n/2 zeros.

Claim. x⋅yx \cdot yx⋅y can be computed with only three products of half-size numbers.

Proof. Expanding, xy=x1y1B2+(x1y0+x0y1)B+x0y0x y = x_1 y_1 B^2 + (x_1 y_0 + x_0 y_1) B + x_0 y_0xy=x1​y1​B2+(x1​y0​+x0​y1​)B+x0​y0​, which seems to need four products. But

(x1+x0)(y1+y0)=x1y1+(x1y0+x0y1)+x0y0(x_1 + x_0)(y_1 + y_0) = x_1 y_1 + (x_1 y_0 + x_0 y_1) + x_0 y_0(x1​+x0​)(y1​+y0​)=x1​y1​+(x1​y0​+x0​y1​)+x0​y0​

so the middle coefficient is (x1+x0)(y1+y0)−x1y1−x0y0(x_1 + x_0)(y_1 + y_0) - x_1 y_1 - x_0 y_0(x1​+x0​)(y1​+y0​)−x1​y1​−x0​y0​. With P1=x1y1P_1 = x_1 y_1P1​=x1​y1​, P2=x0y0P_2 = x_0 y_0P2​=x0​y0​ and P3=(x1+x0)(y1+y0)P_3 = (x_1 + x_0)(y_1 + y_0)P3​=(x1​+x0​)(y1​+y0​), we get xy=P1B2+(P3−P1−P2)B+P2x y = P_1 B^2 + (P_3 - P_1 - P_2) B + P_2xy=P1​B2+(P3​−P1​−P2​)B+P2​: three products, plus additions and shifts, which are O(n)O(n)O(n). ■\blacksquare■

The recurrence is T(n)=3T(n/2)+O(n)T(n) = 3T(n/2) + O(n)T(n)=3T(n/2)+O(n), with a=3>bk=2a = 3 \gt b^k = 2a=3>bk=2, so T(n)∈O(nlog⁡23)≈O(n1.585)T(n) \in O(n^{\log_2 3}) \approx O(n^{1.585})T(n)∈O(nlog2​3)≈O(n1.585) by the division formula.

Euclid's algorithm is correct and fast​

Claim 1. For integers a≥0a \ge 0a≥0 and b>0b \gt 0b>0, gcd⁡(a,b)=gcd⁡(b,a mod b)\gcd(a, b) = \gcd(b, a \bmod b)gcd(a,b)=gcd(b,amodb).

Proof. Write a=qb+ra = q b + ra=qb+r with r=a mod br = a \bmod br=amodb. Any common divisor of aaa and bbb divides r=a−qbr = a - q br=a−qb, so it is a common divisor of bbb and rrr. Conversely, any common divisor of bbb and rrr divides a=qb+ra = q b + ra=qb+r. The two pairs have exactly the same common divisors, so the same greatest one. ■\blacksquare■

Since gcd⁡(a,0)=a\gcd(a, 0) = agcd(a,0)=a, repeating the step until the second number is 0 gives the gcd. The algorithm terminates because the second number is a non-negative integer that strictly decreases (a mod b<ba \bmod b \lt bamodb<b).

Claim 2. Every two iterations, the first number is at least halved, so the algorithm performs O(log⁡a)O(\log a)O(loga) iterations.

Proof. After one iteration the pair (a,b)(a, b)(a,b) becomes (b,r)(b, r)(b,r) with r=a mod br = a \bmod br=amodb; after two, the first number is rrr. If b≤a/2b \le a/2b≤a/2, then r<b≤a/2r \lt b \le a/2r<b≤a/2. If b>a/2b \gt a/2b>a/2, then a mod b=a−b<a/2a \bmod b = a - b \lt a/2amodb=a−b<a/2. Either way, r<a/2r \lt a/2r<a/2. ■\blacksquare■

(The worst case is two consecutive Fibonacci numbers, a result due to Lamé, 1844: the number of iterations is at most about five times the number of decimal digits of the smaller number.)

Quickselect runs in expected linear time​

Quickselect partitions the array around a pivot, as Quicksort does, but recurses only into the part that contains the position it is looking for.

Claim. With a random pivot, the expected number of comparisons is O(n)O(n)O(n) (at most 8n8n8n).

Proof. Call a pivot good if it falls in the middle half of the current range (between the 25% and the 75% positions in sorted order). A random pivot is good with probability 1/21/21/2, and after a good pivot the remaining range has at most 3/43/43/4 of the elements. Divide the execution into phases: phase jjj lasts while the range has between (3/4)j+1n(3/4)^{j+1} n(3/4)j+1n and (3/4)jn(3/4)^j n(3/4)jn elements. Each partition in phase jjj costs at most (3/4)jn(3/4)^j n(3/4)jn comparisons, and the phase ends at the first good pivot, so its expected number of partitions is at most 2 (the expected number of tries until a success with probability 1/21/21/2). Adding over the phases:

E[comparisons]≤∑j≥02(34)jn=2⋅4⋅n=8n\mathbb{E}[\text{comparisons}] \le \sum_{j \ge 0} 2 \left( \frac{3}{4} \right)^j n = 2 \cdot 4 \cdot n = 8nE[comparisons]≤j≥0∑​2(43​)jn=2⋅4⋅n=8n

■\blacksquare■

A more precise analysis gives at most about 3.4 n3.4\,n3.4n comparisons for the median. In the worst case (always the smallest or largest pivot) Quickselect is still O(n2)O(n^2)O(n2); the median-of-medians algorithm of Blum, Floyd, Pratt, Rivest and Tarjan guarantees O(n)O(n)O(n) in every case.

The greedy change is optimal for powers of a base​

The change lesson states that the greedy algorithm is optimal when the coins are 1,p,p2,…,pm1, p, p^2, \dots, p^m1,p,p2,…,pm. We prove a slightly more general result.

Claim. If every coin value divides the next one (c1=1c_1 = 1c1​=1, and ci+1c_{i+1}ci+1​ is a multiple of cic_ici​), and there is an unlimited supply of each coin, the greedy algorithm uses the minimum number of coins for every amount.

Proof. Take an optimal solution and let xix_ixi​ be the number of coins of value cic_ici​ it uses. For every i<mi \lt mi<m, xi⋅ci<ci+1x_i \cdot c_i \lt c_{i+1}xi​⋅ci​<ci+1​: otherwise, the coins of value cic_ici​ would add up to at least ci+1c_{i+1}ci+1​, and since ci+1/cic_{i+1} / c_ici+1​/ci​ is an integer, ci+1/ci≥2c_{i+1} / c_i \ge 2ci+1​/ci​≥2 of them could be replaced by a single coin of value ci+1c_{i+1}ci+1​, using fewer coins. So the coins smaller than ci+1c_{i+1}ci+1​ add up to

∑j≤ixjcj≤∑j≤i(cj+1−cj)=ci+1−1<ci+1\sum_{j \le i} x_j c_j \le \sum_{j \le i} (c_{j+1} - c_j) = c_{i+1} - 1 \lt c_{i+1}j≤i∑​xj​cj​≤j≤i∑​(cj+1​−cj​)=ci+1​−1<ci+1​

(using xjcj≤cj+1−cjx_j c_j \le c_{j+1} - c_jxj​cj​≤cj+1​−cj​, which holds because xjcjx_j c_jxj​cj​ is a multiple of cjc_jcj​ smaller than cj+1c_{j+1}cj+1​). This means that, in an optimal solution, the number of coins of the largest value cmc_mcm​ is exactly ⌊A/cm⌋\lfloor A / c_m \rfloor⌊A/cm​⌋, the maximum that fits, because the rest of the coins add up to less than cmc_mcm​. That is the greedy choice. Repeating the argument with the remaining amount and the smaller coins, the optimal solution coincides with the greedy one. ■\blacksquare■

The condition is sufficient but not necessary: the euro system (1, 2, 5, 10, ...) does not satisfy it, since 2 does not divide 5, and the greedy algorithm is still optimal for it.

The fractional knapsack: highest value per weight first​

Claim. If objects can be split, taking them in decreasing order of vi/wiv_i / w_ivi​/wi​ (and a fraction of the last one) maximizes the value.

Proof (exchange argument). Sort the objects so that v1w1≥v2w2≥…\frac{v_1}{w_1} \ge \frac{v_2}{w_2} \ge \dotsw1​v1​​≥w2​v2​​≥…, and let GGG be the greedy solution and OOO any optimal solution, both filling the knapsack completely (if the objects do not fill it, both take everything). Let iii be the first object that OOO takes in a smaller amount than GGG. Since GGG takes as much as possible of each object in order, OOO must use the missing weight δ\deltaδ on objects j>ij \gt ij>i. Replace in OOO a weight δ\deltaδ of those objects by the same weight of object iii: the value changes by

δ⋅viwi−δ⋅vjwj≥0\delta \cdot \frac{v_i}{w_i} - \delta \cdot \frac{v_j}{w_j} \ge 0δ⋅wi​vi​​−δ⋅wj​vj​​≥0

so the new solution is still optimal and agrees with GGG on one more object. Repeating, we transform OOO into GGG without ever decreasing its value, so GGG is optimal. ■\blacksquare■

The argument fails for the 0/1 knapsack because there we cannot move an arbitrary weight δ\deltaδ: objects are taken whole.

The plumber: shortest tasks first​

Files on a disk: smallest files first​

Claim. To store the largest number of files on a disk of capacity DDD, taking the files from smallest to largest while they fit is optimal.

Proof. Let the files sorted by size be s1≤s2≤⋯≤sns_1 \le s_2 \le \dots \le s_ns1​≤s2​≤⋯≤sn​, and suppose the greedy algorithm stores the first ggg. Any set of mmm files has total size at least s1+⋯+sms_1 + \dots + s_ms1​+⋯+sm​, since those are the mmm smallest. If m>gm \gt gm>g, this sum is at least s1+⋯+sg+1>Ds_1 + \dots + s_{g+1} \gt Ds1​+⋯+sg+1​>D (the greedy algorithm stopped because file g+1g + 1g+1 did not fit). So no set of more than ggg files fits. ■\blacksquare■

(The same rule does not minimize the free space; that problem is the 0/1 knapsack with vi=wiv_i = w_ivi​=wi​.)

The 0/1 knapsack recurrence is correct​

Claim. The value V(i,j)V(i, j)V(i,j) defined by the recurrence of the lesson is the maximum value obtainable with the first iii objects and capacity jjj.

Proof. By induction on iii. For i=0i = 0i=0 there are no objects and the value is 0. For i>0i \gt 0i>0, consider an optimal selection SSS for (i,j)(i, j)(i,j). Either object iii is not in SSS, and then SSS is a selection of the first i−1i - 1i−1 objects with capacity jjj, so its value is at most V(i−1,j)V(i-1, j)V(i−1,j); or object iii is in SSS, and then S∖{i}S \setminus \{i\}S∖{i} is a selection of the first i−1i - 1i−1 objects with capacity j−wij - w_ij−wi​, so its value is at most V(i−1,j−wi)+viV(i-1, j - w_i) + v_iV(i−1,j−wi​)+vi​. In both cases the value is at most the maximum of the recurrence. Conversely, both options of the maximum correspond to valid selections. So the maximum is exactly the optimal value. ■\blacksquare■

This is the principle of optimality in action: the part of an optimal solution that concerns the first i−1i - 1i−1 objects is itself optimal for the capacity it leaves. Filling the (n+1)×(W+1)(n+1) \times (W+1)(n+1)×(W+1) table costs O(nW)O(nW)O(nW).

Pascal's rule​

Claim. (nk)=(n−1k−1)+(n−1k)\binom{n}{k} = \binom{n-1}{k-1} + \binom{n-1}{k}(kn​)=(k−1n−1​)+(kn−1​) for 0<k<n0 \lt k \lt n0<k<n.

Proof. Count the subsets of kkk elements of {1,…,n}\{1, \dots, n\}{1,…,n} according to whether they contain element nnn. Those that contain it are formed by nnn plus k−1k - 1k−1 of the other n−1n - 1n−1 elements: (n−1k−1)\binom{n-1}{k-1}(k−1n−1​). Those that do not are kkk of the other n−1n - 1n−1: (n−1k)\binom{n-1}{k}(kn−1​). ■\blacksquare■

The recursive algorithm that applies this rule reaches the base cases (m0)=(mm)=1\binom{m}{0} = \binom{m}{m} = 1(0m​)=(mm​)=1 exactly (nk)\binom{n}{k}(kn​) times (each base case returns 1, and the result is their sum), so it makes 2(nk)−12\binom{n}{k} - 12(kn​)−1 calls, which is exponential for k=n/2k = n/2k=n/2. The table of dynamic programming has only O(nk)O(nk)O(nk) cells.

The LCS recurrence is correct​
