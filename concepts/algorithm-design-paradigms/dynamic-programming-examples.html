Dynamic Programming in Action

This lesson applies the design steps of dynamic programming to several classic problems: counting combinations, the 0/1 knapsack problem, and two problems on strings, the longest common subsequence and the edit distance. It also proposes two problems from the course to solve yourself: the change and the cheapest travel on a river. The implementations of the course examples are in the course repository.

What you will learn in this lesson
  • How to turn a recursive formula with overlapping subproblems into a table: Pascal's triangle.
  • How to solve the 0/1 knapsack problem optimally, fill its table by hand and recover which objects to take.
  • What a pseudo-polynomial algorithm is.
  • Two classic dynamic programming algorithms on strings: LCS and edit distance.

Combinations​

In mathematics, a combination is a way of selecting kkk things out of a larger group of nnn, where (unlike permutations) the order does not matter. For example, given three fruits (an apple, an orange and a pear), there are three combinations of two: apple and orange, apple and pear, and orange and pear. The number of combinations is the binomial coefficient:

C(n,k)=(nk)=n!k! (n−k)!C(n, k) = \binom{n}{k} = \frac{n!}{k!\,(n-k)!}C(n,k)=(kn​)=k!(n−k)!n!​

Computing it with factorials is risky: n!n!n! overflows a long for n>20n \gt 20n>20, even when the result is small. A better way uses the recurrence behind Pascal's triangle:

C(n,k)={1if k=0 or k=nC(n−1,k−1)+C(n−1,k)if 0<k<nC(n, k) = \begin{cases} 1 & \text{if } k = 0 \text{ or } k = n \\ C(n-1, k-1) + C(n-1, k) & \text{if } 0 \lt k \lt n \end{cases}C(n,k)={1C(n−1,k−1)+C(n−1,k)​if k=0 or k=nif 0<k<n​

(either a given element is in the selection, and we choose the other k−1k - 1k−1 among the remaining n−1n - 1n−1; or it is not, and we choose all kkk among the remaining n−1n - 1n−1).

Question: How many combinations of 9 elements taken 5 at a time are there?

Answer: C(9,5)=9!5! 4!=9⋅8⋅7⋅64⋅3⋅2⋅1=126C(9, 5) = \frac{9!}{5!\,4!} = \frac{9 \cdot 8 \cdot 7 \cdot 6}{4 \cdot 3 \cdot 2 \cdot 1} = 126C(9,5)=5!4!9!​=4⋅3⋅2⋅19⋅8⋅7⋅6​=126.

Divide and conquer: exponential​

The recurrence translates directly into a recursive method:

public long combinationsRecursive(int n, int k) {
    if (k == 0 || k == n) return 1;
    return combinationsRecursive(n - 1, k - 1) + combinationsRecursive(n - 1, k);
}

It has the same problem as Fibonacci: the same subproblems are solved many times. Since every call ends in a base case that returns 1, and the result is the sum of those 1s, computing C(n,k)C(n, k)C(n,k) requires 2 C(n,k)−12\,C(n, k) - 12C(n,k)−1 calls. We measured it:

Dynamic programming: Pascal's triangle​

The different subproblems are the values C(i,j)C(i, j)C(i,j) with 0≤i≤n0 \le i \le n0≤i≤n and 0≤j≤min⁡(i,k)0 \le j \le \min(i, k)0≤j≤min(i,k). Store them in a table, filled row by row, from top to bottom: each cell is the sum of the cell above and the cell above-left.

public long combinationsDP(int n, int k) {
    long[][] table = new long[n + 1][k + 1];
    for (int i = 0; i <= n; i++) {
        for (int j = 0; j <= Math.min(i, k); j++) {
            if (j == 0 || j == i)
                table[i][j] = 1;                                     // borders of the triangle
            else
                table[i][j] = table[i - 1][j - 1] + table[i - 1][j];  // Pascal's rule
        }
    }
    return table[n][k];
}

Complexity. There are O(n⋅k)O(n \cdot k)O(n⋅k) cells, each computed with one addition: O(n⋅k)O(n \cdot k)O(n⋅k) time and memory (or O(k)O(k)O(k) memory keeping only the previous row). Compare with the exponential growth of the recursive version.

The 0/1 Knapsack Problem​

We met the knapsack problem in the greedy chapter. Now the objects cannot be fragmented: each object is either taken entirely or left. We have nnn objects, each with a weight wiw_iwi​ and a value viv_ivi​, and a backpack that can carry a total weight not exceeding WWW; we want to maximize the total value. We saw that no greedy heuristic is optimal for this version. Dynamic programming is.

Data​

Three objects and a weight limit W=10W = 10W=10:

The subproblems and the recurrence​

Subproblems: let V(i,j)V(i, j)V(i,j) be the maximum value we can carry using only the first iii objects, with a weight limit jjj. The solution of the problem is V(n,W)V(n, W)V(n,W), here V(3,10)V(3, 10)V(3,10).

Recurrence: for object iii there are only two options: leave it, or take it (if it fits). If we leave it, the best is V(i−1,j)V(i-1, j)V(i−1,j). If we take it, we gain viv_ivi​, and the remaining capacity j−wij - w_ij−wi​ must be used in the best possible way with the first i−1i - 1i−1 objects (the principle of optimality): V(i−1,j−wi)+viV(i-1, j - w_i) + v_iV(i−1,j−wi​)+vi​. Hence:

The value −∞-\infty−∞ for a negative capacity simply means that an object that does not fit can never be taken.

Recovering the objects​

The table gives the optimal value. To know which objects to take, trace back from V(n,W)V(n, W)V(n,W): if V(i,j)≠V(i−1,j)V(i, j) \ne V(i-1, j)V(i,j)=V(i−1,j), object iii was taken, so continue from V(i−1,j−wi)V(i-1, j - w_i)V(i−1,j−wi​); otherwise, it was not, so continue from V(i−1,j)V(i-1, j)V(i−1,j).

  • V(3,10)=10≠V(2,10)=8V(3, 10) = 10 \ne V(2, 10) = 8V(3,10)=10=V(2,10)=8: object 3 is taken; continue from V(2,5)V(2, 5)V(2,5).
  • V(2,5)=5≠V(1,5)=0V(2, 5) = 5 \ne V(1, 5) = 0V(2,5)=5=V(1,5)=0: object 2 is taken; continue from V(1,0)V(1, 0)V(1,0).
  • V(1,0)=0=V(0,0)V(1, 0) = 0 = V(0, 0)V(1,0)=0=V(0,0): object 1 is not taken.

Solution: objects 2 and 3, with total weight 10 and value 10.

int knapsack01(int maxWeight, int[] weights, int[] values) {
    int n = weights.length;
    int[][] v = new int[n + 1][maxWeight + 1];          // row 0: no objects, all zeros
    for (int i = 1; i <= n; i++)
        for (int j = 0; j <= maxWeight; j++) {
            v[i][j] = v[i - 1][j];                      // leave object i
            if (weights[i - 1] <= j)                    // take it, if it fits
                v[i][j] = Math.max(v[i][j], v[i - 1][j - weights[i - 1]] + values[i - 1]);
        }
    return v[n][maxWeight];
}
🧠 Checkpoint: Fill a table yourself

Question: Four objects with weights 3, 2, 1, 4 and values 6, 4, 5, 10. What is the maximum value with W=6W = 6W=6?

Answer: 15. Several combinations reach it: objects 1, 2 and 3 (weights 3+2+1=63 + 2 + 1 = 63+2+1=6, values 6+4+5=156 + 4 + 5 = 156+4+5=15), or objects 3 and 4 (weights 1+4=51 + 4 = 51+4=5, values 5+10=155 + 10 = 155+10=15). Fill the 5×75 \times 75×7 table to check it.

Complexity: pseudo-polynomial​

The table has (n+1)×(W+1)(n + 1) \times (W + 1)(n+1)×(W+1) cells, each computed in constant time: O(n⋅W)O(n \cdot W)O(n⋅W) in time and memory (memory can be reduced to O(W)O(W)O(W) by keeping a single row, at the cost of not being able to reconstruct the objects).

This looks polynomial, but it depends on the value of WWW, not on its size. WWW is written with about log⁡2W\log_2 Wlog2​W bits, so O(n⋅W)O(n \cdot W)O(n⋅W) is exponential in the size of the input, just like the naive greatest common divisor of the divide and conquer chapter. Such algorithms are called pseudo-polynomial: excellent when WWW is moderate (a few thousand), impractical when WWW is huge (for example, weights in grams of a cargo ship). No algorithm that is polynomial in the size of the input is known for the 0/1 knapsack problem.

Try It Yourself: The Change and the River​

The course proposes two more problems to solve with dynamic programming. Try them before looking for any solution.

The problem of the change​

We want to pay an amount with the fewest possible coins, for any coin system (we saw in the greedy chapter that the greedy heuristic fails for some systems). Hints:

  • The method could be int change(int amount, int[] coins), with the coins sorted from the smallest to the largest, and the first one with a value of 1 (so that every amount can be paid).
  • The structure is very similar to the knapsack: a table with a row for each coin type and a column for each amount from 0 to the total. But now we look for the lowest value instead of the greatest, and each coin can be used many times.
  • With coins of 1, 4, 5, 12, 20, 50, 100 and 200, paying 15 requires 3 coins (5 + 5 + 5). Check that your algorithm finds it, and that the greedy one does not (it would take 12 + 1 + 1 + 1).
  • What is the complexity of your algorithm?

Cheaper travel on the river​

A river has nnn docks. At each one you can rent a boat to go to any other dock downstream (it is impossible to go upstream). A fee table indicates the cost of traveling from dock iii to dock jjj (i<ji \lt ji<j). A trip from iii to jjj may be more expensive than a succession of shorter trips: then it is better to go from iii to some dock kkk and take a second boat from kkk to jjj. Design an efficient algorithm that determines the minimum cost for every pair of docks i<ji \lt ji<j, and indicate its time as a function of nnn.

Hint: think about how a trip from iii to jjj can be split into smaller trips, which subproblems that defines, and in which order the table must be filled so that the values you need are already known.

Beyond the Course: Dynamic Programming on Strings​

Two classic problems show how dynamic programming handles sequences.

Longest common subsequence (LCS)​

A subsequence of a string is obtained by deleting some characters without changing the order of the rest. The longest common subsequence of two strings is the longest string that is a subsequence of both. For example, for ALGORITHM and ALTRUISM, an LCS is ALRIM, of length 5.

Subproblems: L(i,j)L(i, j)L(i,j) = length of the LCS of the first iii characters of aaa and the first jjj characters of bbb.

L(i,j)={0if i=0 or j=0L(i−1,j−1)+1if ai=bjmax⁡(L(i−1,j),  L(i,j−1))otherwiseL(i, j) = \begin{cases} 0 & \text{if } i = 0 \text{ or } j = 0 \\ L(i-1, j-1) + 1 & \text{if } a_i = b_j \\ \max\big(L(i-1, j),\; L(i, j-1)\big) & \text{otherwise} \end{cases}L(i,j)=⎩⎨⎧​0L(i−1,j−1)+1max(L(i−1,j),L(i,j−1))​if i=0 or j=0if ai​=bj​otherwise​

If the last characters match, they are part of the LCS; otherwise, one of them is not, and we keep the best of discarding either one. The table has (∣a∣+1)×(∣b∣+1)(|a| + 1) \times (|b| + 1)(∣a∣+1)×(∣b∣+1) cells: O(∣a∣⋅∣b∣)O(|a| \cdot |b|)O(∣a∣⋅∣b∣). The diff tool that compares versions of a file is based on this idea, applied to lines instead of characters.

Edit distance​

The edit distance (or Levenshtein distance) between two strings is the minimum number of single-character insertions, deletions and substitutions needed to transform one into the other. For example, KITTEN → SITTING needs 3 operations: substitute K by S, substitute E by I, insert G.

D(i,j)=min⁡{D(i−1,j)+1(delete ai)D(i,j−1)+1(insert bj)D(i−1,j−1)+(ai≠bj ? 1:0)(substitute, or keep if equal)D(i, j) = \min \begin{cases} D(i-1, j) + 1 & \text{(delete } a_i\text{)} \\ D(i, j-1) + 1 & \text{(insert } b_j\text{)} \\ D(i-1, j-1) + (a_i \ne b_j\ ?\ 1 : 0) & \text{(substitute, or keep if equal)} \end{cases}D(i,j)=min⎩⎨⎧​D(i−1,j)+1D(i,j−1)+1D(i−1,j−1)+(ai​=bj​ ? 1:0)​(delete ai​)(insert bj​)(substitute, or keep if equal)​
