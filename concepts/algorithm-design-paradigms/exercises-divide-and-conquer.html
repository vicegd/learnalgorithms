Exercises: Brute Force and Divide and Conquer

These exercises review the lessons on brute force and divide and conquer, from the first lesson of the chapter to majority, mode and median. Try each one before reading its solution: the solutions are grouped at the end of the page.

Brute force​

3.1. Pairs that cancel. Given an array of nnn distinct integers, count the pairs of positions i<ji \lt ji<j such that a[i]+a[j]=0a[i] + a[j] = 0a[i]+a[j]=0. Write the brute-force algorithm and give its complexity. Then describe two faster algorithms, one using sorting and one using a hash set.

Analysis​

3.2. Apply the formulas. Give the complexity of each recurrence, identifying aaa, bbb and kkk and the scheme (division or subtraction):

  • (a) T(n)=3T(n/3)+O(n)T(n) = 3T(n/3) + O(n)T(n)=3T(n/3)+O(n)
  • (b) T(n)=8T(n/2)+O(n2)T(n) = 8T(n/2) + O(n^2)T(n)=8T(n/2)+O(n2)
  • (c) T(n)=T(n/2)+O(n)T(n) = T(n/2) + O(n)T(n)=T(n/2)+O(n)
  • (d) T(n)=2T(n/4)+O(n)T(n) = 2T(n/4) + O(\sqrt{n})T(n)=2T(n/4)+O(n​)
  • (e) T(n)=T(n−1)+O(n2)T(n) = T(n-1) + O(n^2)T(n)=T(n−1)+O(n2)
  • (f) T(n)=3T(n−2)+O(1)T(n) = 3T(n-2) + O(1)T(n)=3T(n−2)+O(1)

3.3. Strassen. The classic multiplication of two n×nn \times nn×n matrices performs n3n^3n3 multiplications. Splitting each matrix into four blocks of size n/2n/2n/2, the product needs 8 block products and some additions, O(n2)O(n^2)O(n2). Strassen found how to do it with 7 block products (and more additions, still O(n2)O(n^2)O(n2)). Give the complexity of both divide and conquer versions. For n=1024n = 1024n=1024, how many scalar multiplications does each one perform, if the recursion goes down to 1×11 \times 11×1 blocks?

Designing divide and conquer algorithms​

3.4. Counting inversions. An inversion of an array is a pair of positions i<ji \lt ji<j with a[i]>a[j]a[i] \gt a[j]a[i]>a[j]. The number of inversions measures how far an array is from being sorted (it is used, for example, to compare two rankings). Brute force counts them in O(n2)O(n^2)O(n2). Design an O(nlog⁡n)O(n \log n)O(nlogn) algorithm. Hint: modify Mergesort.

3.5. A peak. A peak of an array is a position whose element is not smaller than its neighbors (the elements at the ends have only one neighbor). Every non-empty array has at least one peak. Find one in O(log⁡n)O(\log n)O(logn).

3.6. A rotated array. A sorted array of distinct integers has been rotated: for example 15 18 22 3 7 9 comes from 3 7 9 15 18 22. Find the minimum in O(log⁡n)O(\log n)O(logn). Does your algorithm still work if the elements may be repeated?

3.7. Integer square root. Compute ⌊n⌋\lfloor \sqrt{n} \rfloor⌊n​⌋ for a long n≥0n \ge 0n≥0 using only integer arithmetic, in O(log⁡n)O(\log n)O(logn) steps. How many iterations does your algorithm need for n=1018n = 10^{18}n=1018?

3.8. The counterfeit coin. Among nnn coins that look identical, exactly one is counterfeit and lighter than the others. You have a two-pan balance. Design an algorithm that finds the counterfeit coin with as few weighings as possible. How many weighings does it need for 27 coins? And for 1,000?

3.9. Median of two arrays. Two sorted arrays a and b have nnn elements each. Find the median of the 2n2n2n elements (take the smaller of the two central elements) in O(log⁡n)O(\log n)O(logn), without merging them.

Solutions​

3.1. Brute force tries every pair:

int count = 0;
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (a[i] + a[j] == 0) count++;

It performs n(n−1)2\frac{n(n-1)}{2}2n(n−1)​ checks: O(n2)O(n^2)O(n2). Two faster options:

  • Sorting, O(nlog⁡n)O(n \log n)O(nlogn): sort the array and move two indices from both ends towards the center. If the sum is positive, move the right index left; if negative, move the left index right; if zero, count it and move both.
  • Hash set, O(n)O(n)O(n) on average: for each element xxx, check whether −x-x−x is already in the set, then add xxx.

Brute force remains the best tool to test the two faster versions on small random arrays.

3.2.

  • (a) Division, a=3a = 3a=3, b=3b = 3b=3, k=1k = 1k=1: a=bka = b^ka=bk, so O(nlog⁡n)O(n \log n)O(nlogn).
  • (b) Division, a=8a = 8a=8, b=2b = 2b=2, k=2k = 2k=2: a=8>bk=4a = 8 \gt b^k = 4a=8>bk=4, so O(nlog⁡28)=O(n3)O(n^{\log_2 8}) = O(n^3)O(nlog2​8)=O(n3).
  • (c) Division, a=1a = 1a=1, b=2b = 2b=2, k=1k = 1k=1: a=1<bk=2a = 1 \lt b^k = 2a=1<bk=2, so O(n)O(n)O(n). The work at the root dominates: n+n/2+n/4+⋯<2nn + n/2 + n/4 + \dots \lt 2nn+n/2+n/4+⋯<2n.
  • (d) Division, a=2a = 2a=2, b=4b = 4b=4, k=1/2k = 1/2k=1/2: bk=4=2=ab^k = \sqrt{4} = 2 = abk=4​=2=a, so O(nlog⁡n)O(\sqrt{n} \log n)O(n​logn). The formula also works with non-integer kkk.
  • (e) Subtraction, a=1a = 1a=1, b=1b = 1b=1, k=2k = 2k=2: O(nk+1)=O(n3)O(n^{k+1}) = O(n^3)O(nk+1)=O(n3).
  • (f) Subtraction, a=3>1a = 3 \gt 1a=3>1, b=2b = 2b=2: O(3n/2)O(3^{n/2})O(3n/2), exponential.

3.3. With 8 products, T(n)=8T(n/2)+O(n2)T(n) = 8T(n/2) + O(n^2)T(n)=8T(n/2)+O(n2): a=8>bk=4a = 8 \gt b^k = 4a=8>bk=4, so O(nlog⁡28)=O(n3)O(n^{\log_2 8}) = O(n^3)O(nlog2​8)=O(n3), no better than the classic algorithm. With 7 products, T(n)=7T(n/2)+O(n2)T(n) = 7T(n/2) + O(n^2)T(n)=7T(n/2)+O(n2): O(nlog⁡27)≈O(n2.807)O(n^{\log_2 7}) \approx O(n^{2.807})O(nlog2​7)≈O(n2.807). For n=1024=210n = 1024 = 2^{10}n=1024=210, the classic method performs 10243≈1.07×1091024^3 \approx 1.07 \times 10^910243≈1.07×109 multiplications, and Strassen's 710≈2.82×1087^{10} \approx 2.82 \times 10^8710≈2.82×108, about 3.8 times fewer. In practice, the recursion stops at blocks of a few dozen elements, because the extra additions make Strassen slower for small matrices. As with Karatsuba, the improvement comes only from reducing aaa.

3.4. Count the inversions of each half recursively, and count the "crossing" inversions (one element in each half) during the merge. When an element of the right half is copied to the output before the remaining elements of the left half, it is smaller than all of them: it forms an inversion with each one.

static long countInversions(int[] a, int[] aux, int left, int right) {
    if (left >= right) return 0;
    int center = left + (right - left) / 2;
    long count = countInversions(a, aux, left, center)
               + countInversions(a, aux, center + 1, right);
    for (int i = left; i <= right; i++) aux[i] = a[i];
    int i = left, j = center + 1, k = left;
    while (i <= center && j <= right) {
        if (aux[i] <= aux[j]) a[k++] = aux[i++];
        else {
            a[k++] = aux[j++];
            count += center - i + 1;    // aux[j] is smaller than aux[i..center]
        }
    }
    while (i <= center) a[k++] = aux[i++];
    while (j <= right) a[k++] = aux[j++];
    return count;
}

The recurrence is that of Mergesort, T(n)=2T(n/2)+O(n)T(n) = 2T(n/2) + O(n)T(n)=2T(n/2)+O(n): O(nlog⁡n)O(n \log n)O(nlogn). For 4 7 1 6 2 it returns 6. We checked it against brute force on 20,000 random arrays. (It sorts the array as a side effect; pass a copy if the original must be kept.)

3.5. Look at the middle element and its right neighbor. If a[mid] < a[mid + 1], the sequence rises to the right, so there is a peak to the right of mid (either the values keep rising until the end, which is a peak, or they fall somewhere, and that point is a peak). Otherwise, there is a peak at mid or to its left.

static int peak(int[] a) {
    int left = 0, right = a.length - 1;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (a[mid] < a[mid + 1]) left = mid + 1;
        else right = mid;
    }
    return left;
}

Half of the range is discarded at each step: O(log⁡n)O(\log n)O(logn). Like binary search, but the array does not need to be sorted.

3.6. Compare the middle element with the last one. If a[mid] > a[right], the rotation point (the minimum) is to the right of mid; otherwise it is at mid or to its left.

static int minRotated(int[] a) {
    int left = 0, right = a.length - 1;
    while (left < right) {
        int mid = left + (right - left) / 2;
        if (a[mid] > a[right]) left = mid + 1;
        else right = mid;
    }
    return a[left];
}

O(log⁡n)O(\log n)O(logn). With repeated elements it can fail: if a[mid] == a[right] (as in 2 2 2 0 2), there is no way to know on which side the minimum is. Discarding only the last element (right--) keeps it correct, but in the worst case (almost all elements equal) the cost becomes O(n)O(n)O(n).

3.7. Binary search over the possible answers: the largest mmm with m2≤nm^2 \le nm2≤n.

static long isqrt(long n) {
    long left = 0, right = Math.min(n, 3_037_000_499L);   // the square of the bound fits in a long
    while (left <= right) {
        long mid = left + (right - left) / 2;
        if (mid * mid <= n) left = mid + 1;
        else right = mid - 1;
    }
    return right;
}

O(log⁡n)O(\log n)O(logn) iterations. For n=1018n = 10^{18}n=1018 the range has about 3×1093 \times 10^93×109 candidates, so about 32 iterations (31 in our run), and the result is 10910^9109. The upper bound avoids overflow when computing mid * mid. (Using Math.sqrt on a double can be wrong by one for large long values, because a double has only 53 bits of precision.)

3.8. Split the coins into three groups as equal as possible and weigh two of them against each other. If one pan is lighter, the counterfeit is in that group; if they balance, it is in the third group. Each weighing keeps one third of the coins: T(n)=T(n/3)+1T(n) = T(n/3) + 1T(n)=T(n/3)+1, so ⌈log⁡3n⌉\lceil \log_3 n \rceil⌈log3​n⌉ weighings. For 27 coins, 3 weighings (33=273^3 = 2733=27). For 1,000 coins, 7 (36=729<1000≤37=21873^6 = 729 \lt 1000 \le 3^7 = 218736=729<1000≤37=2187). Splitting into two halves would need ⌈log⁡2n⌉\lceil \log_2 n \rceil⌈log2​n⌉ weighings (5 and 10): a balance has three outcomes, and dividing by 3 uses all of them.

3.9. Choose how many elements iii of a belong to the lower half of the union (the nnn smallest elements); then j=n−ij = n - ij=n−i come from b. The choice is correct when a[i-1] <= b[j] and b[j-1] <= a[i], and the median is then the larger of a[i-1] and b[j-1]. If a[i-1] > b[j], too many elements were taken from a, so iii must decrease; otherwise it must increase. Binary search on iii between 0 and nnn:

static int median(int[] a, int[] b) {
    int n = a.length, lo = 0, hi = n;
    while (true) {
        int i = (lo + hi) / 2, j = n - i;
        int aLeft  = (i == 0) ? Integer.MIN_VALUE : a[i - 1];
        int aRight = (i == n) ? Integer.MAX_VALUE : a[i];
        int bLeft  = (j == 0) ? Integer.MIN_VALUE : b[j - 1];
        int bRight = (j == n) ? Integer.MAX_VALUE : b[j];
        if (aLeft <= bRight && bLeft <= aRight) return Math.max(aLeft, bLeft);
        if (aLeft > bRight) hi = i - 1;
        else lo = i + 1;
    }
}

Each step halves the range of iii: O(log⁡n)O(\log n)O(logn). We compared it with merging and sorting on 20,000 random pairs of arrays. Merging would cost O(n)O(n)O(n).
