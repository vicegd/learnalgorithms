Sorting by Insertion

⏱ 10 min readRead first: The Sorting Problem · Complexity of Loops

Insertion sort is the method most people use, without thinking, to sort a hand of cards: take the cards one by one and insert each one into its place among the cards already sorted. It is a quadratic algorithm, like bubble sort, but it is much better in practice: it performs fewer comparisons and moves, and it is extremely fast on data that is already almost sorted. For this reason, it is used inside many professional sorting algorithms.

What you will learn in this lesson
  • How direct insertion works, and how to trace it.
  • The exact number of comparisons and moves in the best, worst and average cases, and their relation with inversions.
  • Why insertion sort is adaptive, and why that makes it valuable in practice.
  • Binary insertion, which reduces the comparisons, and why it is still quadratic.

The Idea​

The vector is divided into two "virtual" parts: a sorted sequence on the left and an unsorted sequence on the right. Initially, the sorted part contains only the first element (a single element is always sorted).

In each step, we take the first element of the unsorted sequence and insert it into its corresponding place in the sorted sequence. To make room, the elements of the sorted part that are greater than it are shifted one position to the right. After n−1n - 1n−1 steps, the sorted part covers the whole vector.

public void sort(int[] elements) {
    for (int i = 1; i < elements.length; i++) {
        int key = elements[i];                    // first element of the unsorted part
        int j = i - 1;
        while (j >= 0 && key < elements[j]) {     // shift the greater elements to the right
            elements[j + 1] = elements[j];
            j--;
        }
        elements[j + 1] = key;                    // insert the element in the gap
    }
}

The element being inserted is stored in a variable (called key here, and pivot in some versions of the code) because its position will be overwritten by the shifts. Note that shifting an element requires one assignment, while a swap requires three: insertion sort moves data more cheaply than bubble sort.

Analysis​

When inserting the element at position iii, the inner loop compares it with the elements of the sorted part, from right to left, until it finds one that is not greater (or reaches the beginning). Each element greater than key is shifted once. Therefore, the number of shifts in step iii is the number of elements before position iii that are greater than key: exactly the number of inversions in which key is the second element. Summing over all steps:

The total number of shifts performed by insertion sort is exactly the number of inversions of the input.

And each step performs one comparison per shift, plus (usually) one more comparison that stops the loop.

Compared with bubble sort, insertion sort performs half the comparisons on average (n24\frac{n^2}{4}4n2​ instead of n22\frac{n^2}{2}2n2​), and its moves are shifts (one assignment) instead of swaps (three assignments). It is stable (an element stops as soon as it finds one that is not greater, so it never jumps over an equal element) and in place.

Insertion Sort Is Adaptive​

Since the work is proportional to the number of inversions, the cost of insertion sort is, more precisely,

T(n)=O(n+I)T(n) = O(n + I)T(n)=O(n+I)

where III is the number of inversions of the input. For an almost sorted input, with only a few elements out of place, III is small and the algorithm is practically linear. This is much stronger than the adaptivity of bubble sort with a sentinel, which, as we saw, can still be quadratic when a single element is misplaced (the "turtle" problem). For insertion sort, a single misplaced element costs at most nnn additional shifts, wherever it is.

This property makes insertion sort very valuable in practice:

  • it is the best choice for small arrays, thanks to its very low overhead;
  • it is ideal to maintain a sorted collection to which elements are added one by one;
  • many efficient algorithms use it as a component: Quicksort and Mergesort implementations often switch to insertion sort for small subarrays, and the TimSort algorithm used by Java to sort objects relies on it to process short runs.
🧠 Checkpoint: Almost sorted data

Question: A vector of n=1,000,000n = 1{,}000{,}000n=1,000,000 elements is sorted, except that 10 random elements have been changed to random values. Approximately how much work does insertion sort do? And bubble sort with a sentinel?

Answer: Each of the 10 misplaced elements creates, at most, about nnn inversions, so I≤10nI \le 10nI≤10n and insertion sort performs at most around 10710^7107 shifts plus 10610^6106 comparisons: a few hundredths of a second. Bubble sort with a sentinel depends on where the misplaced elements are: if one of them must move a long way to the right (a "turtle"), it may need a number of passes proportional to nnn, each with up to nnn comparisons: hundreds of billions of operations, which means hours instead of milliseconds.

Binary Insertion​

In each step, the element is inserted into a sorted sequence. We can therefore find its position with binary search instead of comparing it with the elements one by one:

public void sort(int[] elements) {
    for (int i = 1; i < elements.length; i++) {
        int key = elements[i];
        int left = 0;
        int right = i - 1;
        while (left <= right) {                   // binary search of the insertion point
            int center = left + (right - left) / 2;
            if (key < elements[center])
                right = center - 1;
            else
                left = center + 1;                // equal elements: insert after them (stable)
        }
        for (int j = i - 1; j >= left; j--)       // shift to make room
            elements[j + 1] = elements[j];
        elements[left] = key;
    }
}

The number of comparisons drops to about log⁡2i\log_2 ilog2​i per step, that is, about nlog⁡2nn \log_2 nnlog2​n in total, whatever the input. But the number of shifts does not change: the element must still be moved to its place, and all the greater elements must still move one position. In the worst and average cases, the shifts are still O(n2)O(n^2)O(n2), so binary insertion is still quadratic.

It is advantageous when comparisons are expensive (long strings, complex objects) compared with moves. Notice also that it is less adaptive: on sorted data, it performs about nlog⁡2nn \log_2 nnlog2​n comparisons instead of n−1n - 1n−1. The else branch, which moves left to the right when the keys are equal, keeps the algorithm stable.

  • On sorted data, direct insertion is practically instantaneous (linear time), while binary insertion is slower, because it always performs its binary searches.
  • On random and reverse data, both are quadratic (the times multiply by about 4 when nnn doubles), and the reverse case costs about twice the random one, matching the formulas (n22\frac{n^2}{2}2n2​ versus n24\frac{n^2}{4}4n2​ shifts).
  • Direct insertion is 3 to 4 times faster than bubble sort on random data, and binary insertion is faster still, thanks to its fewer comparisons.
Common mistakes
  • Swapping at every step instead of shifting. Shift the larger elements and write the inserted element once.
  • Not stopping the inner loop when the element is in place. That loses the linear best case on sorted data.
  • Using >= instead of > when shifting. Equal elements would jump over each other and the sort would no longer be stable.

Summary​

  • Insertion sort keeps a sorted part on the left and inserts the next element into it, shifting the greater elements.
  • The number of shifts equals the number of inversions: T(n)=O(n+I)T(n) = O(n + I)T(n)=O(n+I). Best case O(n)O(n)O(n); worst and average cases O(n2)O(n^2)O(n2).
  • It performs about half the comparisons of bubble sort, and cheaper moves. It is stable, in place and adaptive.
  • It is the best simple algorithm in practice, the best choice for small or almost sorted arrays, and a building block of efficient hybrid algorithms.
  • Binary insertion reduces the comparisons to O(nlog⁡n)O(n \log n)O(nlogn), but the moves remain O(n2)O(n^2)O(n2).
