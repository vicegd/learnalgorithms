Exercises: Sorting

These exercises review the whole sorting chapter. They use the versions of the algorithms given in the lessons (for example, the bubble sort of the lesson moves the smallest elements to the left, scanning from right to left). Try each exercise before reading its solution: the solutions are grouped at the end of the page.

The sorting problem​

2.1. Is it sorted correctly? A student checks his sorting method with a test that only verifies that the output is in ascending order. Give a wrong "sorting" method that passes this test for every input. What else must the test check?

2.2. Stability. For each algorithm, say whether it is stable as written in the lessons: bubble sort, insertion sort, selection sort, Quicksort, Mergesort, Heapsort. For one of the unstable ones, give a small array that shows it.

2.3. Sorting by two keys. A list of students must be sorted by grade, and students with the same grade must appear in alphabetical order. You have a stable sorting method that sorts by any single field. In which order should you sort, by name first or by grade first? Why?

Simple algorithms​

2.4. Inversions. How many inversions does the array 4 7 1 6 2 have? How many swaps will bubble sort perform on it? And insertion sort, how many element shifts?

Solution to 2.4 ↓

2.5. Rabbits and turtles. Apply the bubble sort with sentinel of the lesson (passes from right to left, stopping when a pass makes no swap) to 2 3 4 5 6 1 and to 6 1 2 3 4 5. How many passes does each one need? Explain the difference, and say which elements are the "turtles" for this version of the algorithm.

Solution to 2.5 ↓

2.6. Insertion sort and nearly sorted data. Prove that the number of comparisons made by insertion sort is at least III and at most I+n−1I + n - 1I+n−1, where III is the number of inversions of the input. Deduce the cost of insertion sort on an array where every element is at most ddd positions away from its final position.

Solution to 2.6 ↓

2.7. Few swaps. How many swaps does selection sort perform on an array in descending order, n n-1 ... 2 1? (Try n=6n = 6n=6 and n=7n = 7n=7 by hand.) Why is it not n−1n - 1n−1?

Limits and choices​

2.14. Sorting five elements. What is the minimum number of comparisons that any comparison-based algorithm needs, in the worst case, to sort 5 elements? Is that bound achievable?

2.15. Without comparisons. Which algorithm would you use, and with what cost, to sort:

  • (a) the ages (integers from 0 to 120) of the 47 million inhabitants of a country;
  • (b) 10910^9109 arbitrary 32-bit integers, using Radix sort with base 256?

2.16. Choosing. Which sorting algorithm would you choose in each situation, and why?

  • (a) A large array that is already sorted except for a few elements appended at the end.
  • (b) An embedded system with very little memory that must guarantee O(nlog⁡n)O(n \log n)O(nlogn) in every case.
  • (c) A list of Employee objects that must keep the previous order of employees with equal salaries.
  • (d) 500 GB of records on disk, on a computer with 16 GB of memory.

Solution to 2.16 ↓

Solutions​

2.1. A method that writes zeros in every position, or simply returns [1, 2, ..., n], passes the test. A correct test must also check that the output is a permutation of the input: the same elements, the same number of times. A simple way is to sort a copy with a trusted method (Arrays.sort) and compare the arrays; another is to compare the frequency of each value before and after.

↑ Back to exercise 2.1

2.2. Stable: bubble sort, insertion sort and Mergesort (when, in the merge, equal elements are taken from the left half first). Unstable: selection sort, Quicksort and Heapsort. Example for selection sort: 2a 2b 1. The first step swaps the minimum 1 with the element in position 0, 2a, giving 1 2b 2a: the two 2s have changed their relative order.

↑ Back to exercise 2.2

2.3. By name first, then by grade. The second sort decides the main order (grade). Because it is stable, students with the same grade keep the order they had after the first sort, which was alphabetical. Sorting in the other order would leave the list sorted by name, with grades mixed. This is how spreadsheets and many databases sort by several columns.

↑ Back to exercise 2.3

2.4. The inversions are the pairs out of order: (4,1), (4,2), (7,1), (7,6), (7,2), (6,2), so 6 inversions. Every swap of adjacent elements removes exactly one inversion, so bubble sort performs 6 swaps, and insertion sort performs 6 shifts. Running the bubble sort with sentinel on this array confirms it: 6 swaps, in 4 passes and 10 comparisons.

↑ Back to exercise 2.4

2.5. 2 3 4 5 6 1 needs 2 passes: in the first one, the 1 travels all the way from the end to the front, and the second pass finds nothing to swap. 6 1 2 3 4 5 needs 5 passes (with 15 comparisons), the maximum for n=6n = 6n=6: the 6 can only move one position to the right per pass, because each pass carries small elements to the left. For this version of the algorithm, the turtles are large elements near the beginning; the rabbits are small elements near the end. (The version that scans from left to right has the opposite behavior. Bidirectional bubble sort alternates both directions to move both kinds quickly.)

↑ Back to exercise 2.5

2.6. Each comparison key < elements[j] either succeeds, and then key passes over an element larger than itself (removing one inversion), or fails, and then the insertion of that key ends. So there are exactly III successful comparisons plus at most one failed comparison for each of the n−1n - 1n−1 insertions: between III and I+n−1I + n - 1I+n−1 comparisons. (On random arrays of 20 elements we counted, for example, 103 comparisons with I=87I = 87I=87, inside the range 87 to 106.) If every element is at most ddd positions away from its final place, an element yyy that is larger than xxx and stands to its left must be among the 2d−12d - 12d−1 positions just before xxx (otherwise one of the two would be more than ddd positions away from its place). So each element forms fewer than 2d2d2d inversions with the elements to its left, I<2dnI \lt 2dnI<2dn, and the cost is O(n⋅d)O(n \cdot d)O(n⋅d): linear for constant ddd. This is why insertion sort is used for nearly sorted data.

↑ Back to exercise 2.6

2.7. ⌊n/2⌋\lfloor n/2 \rfloor⌊n/2⌋ swaps: 3 for n=6n = 6n=6 and also 3 for n=7n = 7n=7. The first step swaps the first and last elements (n and 1), which puts both in their final positions. The same happens with the second and the next-to-last, and so on, so after ⌊n/2⌋\lfloor n/2 \rfloor⌊n/2⌋ swaps every remaining minimum is already in place and the algorithm (which skips the swap when i == posMin) swaps nothing else.

↑ Back to exercise 2.7

2.8. Recurse only on the smaller part and handle the larger part with a loop:

private void quickSortIterative(int[] elements, int left, int right) {
    while (right - left >= 3) {
        int p = partition(elements, left, right);   // the partition of the lesson
        if (p - left < right - p) {                 // left part is smaller
            quickSortIterative(elements, left, p - 1);
            left = p + 1;                           // continue with the right part
        } else {
            quickSortIterative(elements, p + 1, right);
            right = p - 1;                          // continue with the left part
        }
    }
    sortSmall(elements, left, right);               // 3 elements or fewer
}

Here partition is the partition loop of the lesson, moved to a method that returns the final position of the pivot, and sortSmall is the medianOfThree call, which already sorts ranges of 3 elements or fewer. Every recursive call receives at most half of the current range, so there can be at most log⁡2n\log_2 nlog2​n nested calls. The time in the worst case is still O(n2)O(n^2)O(n2); only the memory is protected.

↑ Back to exercise 2.8

2.9.

  • (a) An array that is already sorted (or in reverse order): every partition leaves one part empty.
  • (b) There are inputs that defeat it, but they are not "natural": they must be built on purpose, placing the smallest (or largest) remaining element in the center of each subarray. Sorted and reversed arrays, which defeat (a), are the best case for (b).
  • (c) No fixed input is bad for a random pivot. The expected time is O(nlog⁡n)O(n \log n)O(nlogn) for every input; quadratic time is possible only through extremely unlikely random choices. This is the main argument for randomized pivots: they protect against inputs crafted by an adversary.

↑ Back to exercise 2.9

2.10. n=6n = 6n=6, so downHeap runs on positions 2, 1 and 0:

  • Position 2 (2): its only child is 5 (position 5). Swap: 3 9 5 1 4 2.
  • Position 1 (9): its children are 1 and 4; 9 is larger. No change.
  • Position 0 (3): its children are 9 and 5; swap with 9: 9 3 5 1 4 2. Continue at position 1 (3): children 1 and 4; swap with 4: 9 4 5 1 3 2.

Result: 9 4 5 1 3 2. Each parent is greater than or equal to its children.

↑ Back to exercise 2.10

2.11. Each comparison places one element in the output, and the merge stops comparing when one of the lists is empty. Best case: every element of the shorter list is smaller than every element of the longer one, min⁡(m,k)\min(m, k)min(m,k) comparisons; for example 1 2 3 and 4 5 6 7 need 3. Worst case: both lists are exhausted at the very end, m+k−1m + k - 1m+k−1 comparisons; for example 2 4 6 and 1 3 5 7 need 6.

↑ Back to exercise 2.11

2.12. Put the first element of each list in a min-heap (a PriorityQueue), together with the index of its list. Repeatedly extract the minimum, append it to the output, and insert the next element from the same list. The heap never has more than kkk elements, so each of the NNN extractions and insertions costs O(log⁡k)O(\log k)O(logk): O(Nlog⁡k)O(N \log k)O(Nlogk) in total. Merging the lists two by two in a balanced way (as Mergesort does) gives the same bound.

↑ Back to exercise 2.12

2.13. A min-heap of size 10. For each new number, if the heap has fewer than 10 elements, insert it; otherwise, if the number is larger than the minimum of the heap (its root), replace the root and restore the heap. At the end, the heap holds the 10 largest. Each step costs O(log⁡k)O(\log k)O(logk) with k=10k = 10k=10, so the total is O(nlog⁡k)O(n \log k)O(nlogk), practically linear, with O(k)O(k)O(k) memory.

↑ Back to exercise 2.13

2.14. There are 5!=1205! = 1205!=120 possible orders, and each comparison has two outcomes, so at least ⌈log⁡2120⌉=7\lceil \log_2 120 \rceil = 7⌈log2​120⌉=7 comparisons are needed in the worst case. The bound is achievable: there is an algorithm (merge insertion, by Ford and Johnson) that sorts any 5 elements with exactly 7 comparisons. Mergesort needs 8 in its worst case for n=5n = 5n=5.

↑ Back to exercise 2.14

2.15.

  • (a) Counting sort: an array of 121 counters, one pass to count and one to write the result. O(n+k)O(n + k)O(n+k) with k=121k = 121k=121: linear, and much faster than any comparison sort for 47 million elements.
  • (b) Radix sort with base 256=28256 = 2^8256=28: four passes of counting sort, one per byte of the 32-bit integers, each O(n+256)O(n + 256)O(n+256). In total, O(4(n+256))=O(n)O(4 (n + 256)) = O(n)O(4(n+256))=O(n). (Negative numbers need care: the most significant byte must be treated with the sign bit inverted.)

↑ Back to exercise 2.15

2.16.

  • (a) Insertion sort, or the library's TimSort (Arrays.sort for objects, List.sort), which detects sorted runs. Both are close to linear when few elements are out of place.
  • (b) Heapsort: O(nlog⁡n)O(n \log n)O(nlogn) in every case and O(1)O(1)O(1) additional memory.
  • (c) A stable algorithm: Mergesort, or the library's TimSort, which is stable. Quicksort and Heapsort would not respect the previous order.
  • (d) External sorting: sort the data in chunks of about 16 GB in memory, write each sorted chunk to disk, and merge the chunks with a kkk-way merge (exercise 2.12), reading and writing the disk sequentially.

↑ Back to exercise 2.16
