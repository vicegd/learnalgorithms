Proofs: Sorting

This page proves the claims made in the sorting lessons: that each algorithm sorts correctly, the costs given in the lessons, and the limits that no comparison-based algorithm can break. The proofs use loop invariants and induction, explained in Induction, Correctness and Recurrences. Arrays are indexed from 0 and have nnn elements.

Bubble sort is correct​

The bubble sort of the lessons performs passes i=1,…,n−1i = 1, \dots, n - 1i=1,…,n−1; each pass scans from the right end down to position iii, swapping adjacent elements that are out of order.

Invariant. After pass iii, the positions 0,…,i−10, \dots, i - 10,…,i−1 hold the iii smallest elements, in order.

Proof. During pass iii, the scan carries a minimum mmm of elements[i-1..n-1] to position i−1i - 1i−1. From the moment the scan meets a copy of mmm, the element at the current scan position is always equal to mmm: if its left neighbor is larger, they are swapped; if the neighbor is also equal to mmm, the scan simply continues with that copy. Before the pass, by the invariant for i−1i - 1i−1, positions 0,…,i−20, \dots, i - 20,…,i−2 hold the i−1i - 1i−1 smallest elements in order, and the pass never touches them. So after the pass, position i−1i - 1i−1 holds the smallest of the rest, which is the iii-th smallest overall. After pass n−1n - 1n−1, the first n−1n - 1n−1 positions hold the n−1n - 1n−1 smallest in order, and the last position holds the largest: the array is sorted. ■\blacksquare■

The sentinel. If a pass makes no swap, every pair of adjacent elements in elements[i-1..n-1] is in order, so that part is sorted; together with the invariant, the whole array is sorted, and stopping is correct.

Insertion sort is correct​

Invariant. Before processing position iii, the subarray elements[0..i-1] contains the original first iii elements, in order.

Proof. For i=1i = 1i=1, a single element is sorted. When position iii is processed, the key elements[i] is saved, and the elements of the sorted prefix that are greater than the key are shifted one position to the right, starting from the end, until an element not greater than the key (or the start of the array) is found. The key is written in the gap. The elements to the left of the gap are at most the key, those to its right are greater, and both groups keep their order: elements[0..i] is sorted. At the end (i=ni = ni=n) the whole array is sorted. ■\blacksquare■

Because the loop stops at the first element not greater than the key, equal elements are never moved past each other: insertion sort is stable.

Selection sort is correct​

Invariant. After iteration iii, positions 0,…,i0, \dots, i0,…,i hold the i+1i + 1i+1 smallest elements, in order.

Proof. Iteration iii finds the minimum of elements[i..n-1] and swaps it into position iii. By the invariant for i−1i - 1i−1, everything before position iii is smaller than or equal to everything from iii on, so the minimum of the rest is the (i+1)(i+1)(i+1)-th smallest element. After iteration n−2n - 2n−2, the last element is the largest. ■\blacksquare■

The number of comparisons does not depend on the input: ∑i=0n−2(n−1−i)=n(n−1)2\sum_{i=0}^{n-2} (n - 1 - i) = \frac{n(n-1)}{2}∑i=0n−2​(n−1−i)=2n(n−1)​.

Adjacent swaps need quadratic time​

The bubble sort lesson argues that algorithms that only swap adjacent elements are slow. Here is the proof.

Claim 1. Swapping two adjacent elements changes the number of inversions by exactly one.

Proof. An inversion is a pair of positions i<ji \lt ji<j with ai>aja_i \gt a_jai​>aj​. Swapping aka_kak​ and ak+1a_{k+1}ak+1​ does not change the relative order of any pair except that pair itself. So the number of inversions changes by exactly one: it decreases if they were out of order, and increases otherwise. ■\blacksquare■

A sorted array has no inversions, so any algorithm that only swaps adjacent elements performs at least III swaps, where III is the number of inversions of the input.

Claim 2. A random permutation of nnn distinct elements has n(n−1)4\frac{n(n-1)}{4}4n(n−1)​ inversions on average.

Proof. Each of the (n2)=n(n−1)2\binom{n}{2} = \frac{n(n-1)}{2}(2n​)=2n(n−1)​ pairs of positions is an inversion in exactly half of the permutations: reversing a permutation turns each inversion into a non-inversion and vice versa. So each pair contributes 12\frac{1}{2}21​ to the expected count. ■\blacksquare■

Combining both: bubble sort, insertion sort and any other algorithm based on adjacent swaps need Ω(n2)\Omega(n^2)Ω(n2) swaps on average, not only in the worst case. Efficient algorithms must move elements over long distances, as Shellsort, Heapsort, Mergesort and Quicksort do.

No comparison sort can beat n log n​

Claim. Every sorting algorithm that only obtains information by comparing elements needs at least ⌈log⁡2(n!)⌉\lceil \log_2 (n!) \rceil⌈log2​(n!)⌉ comparisons in the worst case, which is Ω(nlog⁡n)\Omega(n \log n)Ω(nlogn).

Proof. Represent the algorithm, for a fixed nnn, as a decision tree: each internal node is a comparison "is ai<aja_i \lt a_jai​<aj​?", its two children are the two possible outcomes, and each leaf is the moment the algorithm finishes, having determined the order of the input. Two different permutations of distinct elements must reach different leaves, because they require different rearrangements. So the tree has at least n!n!n! leaves. A binary tree of height hhh has at most 2h2^h2h leaves, so 2h≥n!2^h \ge n!2h≥n! and

h≥log⁡2(n!)≥log⁡2((n2)n/2)=n2log⁡2n2h \ge \log_2 (n!) \ge \log_2 \left( \left( \frac{n}{2} \right)^{n/2} \right) = \frac{n}{2} \log_2 \frac{n}{2}h≥log2​(n!)≥log2​((2n​)n/2)=2n​log2​2n​

using that the largest n/2n/2n/2 factors of n!n!n! are each at least n/2n/2n/2. The height is the number of comparisons in the worst case. ■\blacksquare■

The same argument applied to the average depth of the leaves shows that the bound also holds on average. Mergesort and Heapsort, with O(nlog⁡n)O(n \log n)O(nlogn) in the worst case, are therefore asymptotically optimal. Algorithms such as counting sort and radix sort escape the bound because they do not only compare: they use the values as array indices.

Quicksort's partition is correct​

The Quicksort of the lessons hides the pivot at the end of the range and moves two indices, i from the left and j from the right.

Invariant. At every moment, all elements to the left of i are at most the pivot, and all elements to the right of j (and before the hidden pivot) are at least the pivot.

Proof. Initially both regions are empty. The first inner loop advances i over elements at most the pivot, and the second moves j back over elements at least the pivot, which keeps the invariant. When both stop with i < j, elements[i] is greater than the pivot and elements[j] is smaller; swapping them extends both regions. When the indices cross, every element before i is at most the pivot and every element from i on is at least the pivot, so swapping the pivot into position i puts it in its final position. ■\blacksquare■

Quicksort is then correct by strong induction on the size: both recursive calls receive smaller ranges (the pivot is excluded), sort them by the induction hypothesis, and the pivot between them is already in place.

Mergesort is correct and costs n log n​

Merge. The merge of two sorted halves repeatedly copies the smaller of their first remaining elements. Invariant: the output written so far contains the smallest elements of both halves, in order. Each step preserves it, because the smallest remaining element of the union is the first remaining element of one of the halves. When one half is exhausted, the rest of the other half is copied, and it is already sorted and not smaller than anything written. So the merge is correct. Taking the element of the left half when two are equal makes Mergesort stable.

Cost. Merging nnn elements takes at most n−1n - 1n−1 comparisons and exactly nnn copies, so T(n)=2T(n/2)+Θ(n)T(n) = 2T(n/2) + \Theta(n)T(n)=2T(n/2)+Θ(n), which is Θ(nlog⁡n)\Theta(n \log n)Θ(nlogn) by the division formula. The recursion tree has log⁡2n\log_2 nlog2​n levels and each level copies all nnn elements once. ■\blacksquare■

Radix sort is correct​

The least-significant-digit radix sort sorts the numbers by their last digit, then by the next one, and so on, with a stable sort at each step (counting sort or buckets).

Invariant. After ddd passes, the numbers are sorted by their last ddd digits (as numbers formed by those digits).

Proof. By induction on ddd. Pass d+1d + 1d+1 sorts by digit d+1d + 1d+1 (counting from the right). Two numbers with different digits there end up in the right order by that digit, which decides the comparison of their last d+1d + 1d+1 digits. Two numbers with the same digit keep their previous relative order, because the pass is stable, and by the induction hypothesis that order was correct for the last ddd digits. After as many passes as the numbers have digits, they are fully sorted. ■\blacksquare■

Stability is essential: with an unstable sort in each pass, the order established by the previous passes would be lost.
