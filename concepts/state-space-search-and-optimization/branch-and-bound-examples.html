Branch and Bound: Classic Problems

This lesson applies the general scheme of branch and bound to several problems. In each one, the work consists of answering the same three questions:

  1. What is a state, and what are its children?
  2. What is the heuristic (the lower bound, for minimization) that orders the live nodes and decides what to prune?
  3. What is the initial pruning limit?

Task assignment​

Problem. There are nnn agents and nnn tasks. Each agent performs exactly one task and each task is performed by exactly one agent. The cost of agent iii performing task jjj is C[i][j]C[i][j]C[i][j]. Find the assignment with minimum total cost. (This problem was solved by backtracking in the previous lesson; now we solve it with branch and bound.)

We use this cost matrix, with agents a,b,c,da, b, c, da,b,c,d and tasks 1 to 4:

Agent \ Task1234
a11121840
b14151322
c11171923
d17142028

Design​

  • State: the tasks assigned to the first kkk agents. Level kkk decides the task of agent k+1k + 1k+1, so each node has one child per task still free. When only one agent is left, its task is forced, so the last two agents are decided together.
  • Heuristic (lower bound): the sum of the costs already assigned, plus, for each task still free, the minimum cost in its column among the agents still free. Each remaining task will be done by someone, and at best by its cheapest remaining agent, so this never overestimates. (It may be too optimistic: the same agent could be the cheapest for two tasks.)
  • Initial pruning limit: the cheaper of the two diagonals of the matrix. Each diagonal is a valid assignment (agent iii gets task iii, or task n+1−in + 1 - in+1−i), so the optimum cannot be worse:
U0=min⁡(11+15+19+28,  40+13+17+17)=min⁡(73,87)=73U_0 = \min(11 + 15 + 19 + 28,\; 40 + 13 + 17 + 17) = \min(73, 87) = 73U0​=min(11+15+19+28,40+13+17+17)=min(73,87)=73

For example, the state "a gets task 1" has heuristic 111111 (assigned) +min⁡(15,17,14)+ \min(15, 17, 14)+min(15,17,14) (column 2) +min⁡(13,19,20)+ \min(13, 19, 20)+min(13,19,20) (column 3) +min⁡(22,23,28)+ \min(22, 23, 28)+min(22,23,28) (column 4) =11+14+13+22=60= 11 + 14 + 13 + 22 = 60=11+14+13+22=60.

At scale​

On random n×nn \times nn×n matrices with costs between 1 and 99, we compared this B&B with the backtracking algorithm of the previous lesson (which prunes only when the cost so far reaches the best cost):

Both return the same optimum. The difference comes from the estimate of the future cost: backtracking only knows what has already been spent, while the B&B bound also accounts for what must still be spent, so it detects hopeless branches much earlier. 0/1 knapsack​

Problem. We have nnn objects with weights wiw_iwi​ and values viv_ivi​, and a knapsack with capacity WWW. Choose objects (each one entirely or not at all) to maximize the total value without exceeding the capacity. We solved it with dynamic programming in pseudo-polynomial time; branch and bound solves it without depending on the size of WWW.

Design​

  • State: decisions taken for the first kkk objects (take it or leave it), with the weight and value accumulated. Each node has at most two children.
  • This is a maximization problem, so everything is mirrored: the bound is an optimistic upper bound on the value reachable from the node, the benchmark is the best value found so far, and a node is pruned when its bound is less than or equal to that value.
  • Bound: sort the objects by value per unit of weight vi/wiv_i / w_ivi​/wi​, decreasing. From the current state, keep adding the remaining objects in that order while they fit, and fill the remaining capacity with a fraction of the next one. This is the greedy solution of the fractional knapsack, which is optimal for the relaxed problem, so it can never be worse than the true best completion.

Example​

Use the instance from the dynamic programming lesson: W=10W = 10W=10, and three objects with weights 6,5,56, 5, 56,5,5 and values 8,5,58, 5, 58,5,5 (ratios 1.331.331.33, 111, 111, already sorted).

  • Root: take object 1 (weight 6, value 8), 4 units of capacity left, take 4/54/54/5 of object 2 (value 4): bound =12= 12=12.
  • Expand the root:
    • "take 1": value 8, bound 8+4=128 + 4 = 128+4=12. The best value so far becomes 8.
    • "leave 1": objects 2 and 3 fit: bound =10= 10=10.
  • Expand "take 1" (12). Object 2 does not fit. Leaving it gives bound 8+45⋅5=128 + \tfrac{4}{5} \cdot 5 = 128+54​⋅5=12; expanding that, object 3 does not fit either, and the complete solution has value 8.
  • Expand "leave 1" (its bound, 10, is greater than 8). "Take 2": value 5, bound 10. "Leave 2": bound 5 ≤ 8, pruned.
  • Expand "take 2" (10). "Take 3": value 10, which becomes the best value. "Leave 3": bound 5, pruned.
  • No live node can beat 10: stop. The optimum is objects 2 and 3, value 10.

The example also shows that the first branch explored (the one with the most attractive bound) does not always contain the optimum: the fractional bound of "take 1" was 12, but its true best completion is only 8. The bound was optimistic, as required, and the search corrected itself.

The power of a tight bound​

On 30 random objects (weights between 10 and 99, capacity half of the total weight):

AlgorithmNodes or callsTime
Backtracking, pruning only objects that do not fitabout 1,207 million calls2.3 s
Backtracking + fractional bound251 calls0.2 ms
Best-first B&B + fractional bound122 nodes expanded1.6 ms

All three return the same value. The bound is responsible for almost all of the improvement; the best-first order then halves the number of nodes, at the price of creating node objects and managing a priority queue. On instances with 40 and 50 objects, the bounded versions still need only a few hundred nodes.

Sliding puzzles​

Problem. The 15-puzzle is played on a 4×44 \times 44×4 board with 15 numbered tiles and one empty cell. A move slides a tile adjacent to the empty cell into it (equivalently, the empty cell moves to one of its up to four neighbors). Pieces cannot be lifted. Starting from a scrambled board, reach the goal state with the tiles in order and the empty cell in the last position, using as few moves as possible. The 8-puzzle is the same game on a 3×33 \times 33×3 board.

Initial state           Goal state
14  2  3 12              1  2  3  4
 9  .  4  8              5  6  7  8

 5  1 15  6             13 14 15  .

The state space​

The board can be in 16!≈2.1×101316! \approx 2.1 \times 10^{13}16!≈2.1×1013 configurations. Only half of them can be reached from a given initial state, but that is still about 101310^{13}1013 states: building and exploring the whole tree is unacceptable. Before searching, we should know whether the goal is reachable at all.

Reachability test​

Number the cells from 1 to 16, row by row, and treat the empty cell as tile 16. Define:

  • position(i)\text{position}(i)position(i): the cell where tile iii is in the initial state;
  • smaller(i)\text{smaller}(i)smaller(i): the number of tiles j<ij \lt ij<i such that position(j)>position(i)\text{position}(j) \gt \text{position}(i)position(j)>position(i) (smaller tiles that appear after tile iii);
  • x=1x = 1x=1 if the empty cell is in one of the shaded cells of a checkerboard pattern (cells 2, 4, 5, 7, 10, 12, 13 and 15), and x=0x = 0x=0 otherwise.

Then the goal state is reachable if and only if

∑i=116smaller(i)+x is even.\sum_{i=1}^{16} \text{smaller}(i) + x \text{ is even.}i=1∑16​smaller(i)+x is even.

The reason is a parity argument: every move changes the parity of the number of inversions (horizontal moves by exactly one inversion, vertical moves by an odd number) and also changes the color of the square where the empty cell is, so the parity of the total never changes. The goal has sum 0 and x=0x = 0x=0.

Heuristics​

Two classic estimates of how far a board is from the goal:

  • Misplaced tiles: the number of tiles that are not in their final cell.
  • Manhattan distance: the sum, over all tiles, of the number of rows plus columns that separate each tile from its final cell.

Both are admissible: each misplaced tile needs at least one move, and each move changes the Manhattan distance of only one tile by one. The empty cell must not be counted, or the estimate may exceed the true number of moves. Manhattan distance is always at least as large as the number of misplaced tiles, so it is the tighter (better) of the two.

Ordering the live nodes: g+hg + hg+h​

To find the solution with the fewest moves, the priority of a board xxx must be

f(x)=g(x)+h(x)f(x) = g(x) + h(x)f(x)=g(x)+h(x)

where g(x)g(x)g(x) is the number of moves already made from the initial state and h(x)h(x)h(x) an admissible heuristic. This is the A* algorithm described in the previous lesson. The B&B must also discard repeated states: otherwise it would keep generating boards it has already seen, moving tiles back and forth.

We solved 200 random solvable 8-puzzles with four strategies:

Breadth-first (FIFO queue)22.3 (optimal)83,701

The three strategies that include ggg always find the shortest solution, and the better the heuristic, the fewer boards they expand. The last one expands fewer boards still, but its solutions are almost three times longer than necessary: in 194 of the 200 puzzles it returned a non-optimal solution, in one case with 142 extra moves. Forgetting ggg turns branch and bound into a greedy search.

Rectangle placement​

Problem. We have nnn flat rectangular pieces p1,…,pnp_1, \dots, p_np1​,…,pn​, where piece pip_ipi​ measures ai×bia_i \times b_iai​×bi​. We want to place them on a flat board, without overlapping, so that the area of the rectangle that encloses all of them is minimum. A real application is arranging boxes in a warehouse with robotic arms, or cutting pieces from a sheet of material with minimum waste.

For example, with p1=1×2p_1 = 1 \times 2p1​=1×2, p2=2×2p_2 = 2 \times 2p2​=2×2 and p3=1×3p_3 = 1 \times 3p3​=1×3, different arrangements need enclosing boxes of 4×3=124 \times 3 = 124×3=12, 7×2=147 \times 2 = 147×2=14, 5×2=105 \times 2 = 105×2=10 or 3×3=93 \times 3 = 93×3=9. The last one is optimal: the pieces have a total area of 2+4+3=92 + 4 + 3 = 92+4+3=9, so they fill the 3×33 \times 33×3 square without gaps (the 2×22 \times 22×2 piece in a corner, the 1×21 \times 21×2 piece standing next to it, and the 1×31 \times 31×3 piece along the remaining side).

Design​

  • State: a matrix of integers representing the board, where 0 marks a free cell and a value k>0k \gt 0k>0 marks a cell occupied by piece pkp_kpk​. At step kkk the next piece not yet placed is added.
  • Children: one child for each valid position of the next piece, both horizontal and vertical. A position is valid if it does not overlap the pieces already placed and is adjacent to at least one of them (placing a piece far away can only make the box bigger).
  • Solution: a node at level nnn (all pieces placed). The problem always has a solution if the board is large enough.
  • Bound: the area of the enclosing box of the pieces placed so far can only grow when more pieces are added, so it is a valid lower bound. A node is pruned when that area already reaches the area of the best solution found.

A stronger bound uses the fact that the final box must also contain the area of the pieces not yet placed: max⁡(current box area,total area of all pieces)\max(\text{current box area}, \text{total area of all pieces})max(current box area,total area of all pieces).

N-queens​

Branch and bound is not only for optimization. Here it is used to find one placement of nnn non-attacking queens (the problem solved by backtracking) as fast as possible. Only states in which no queen attacks another are generated.

Branching heuristic​

  1. Develop first the state with more queens placed: it is closer to a solution.
  2. In case of a tie, prefer the state whose last queen is on a cell whose longest diagonal is the shortest. A queen on a short diagonal attacks fewer cells, so it leaves more room for the remaining queens.

Let diagonal(i,j)\text{diagonal}(i, j)diagonal(i,j) be the length of the longest diagonal passing through cell (i,j)(i, j)(i,j). For a 5×55 \times 55×5 board:

To merge both criteria into one number (lower is better), the first criterion is multiplied by 10 so that it always dominates the second:

h=(n−queens placed)⋅10+diagonal(i,j)h = (n - \text{queens placed}) \cdot 10 + \text{diagonal}(i, j)h=(n−queens placed)⋅10+diagonal(i,j)

For n=5n = 5n=5, the five children of the root (one queen in the first column) get the values 45, 44, 43, 44 and 45, so the search starts with the queen in the middle row of the first column, on the short diagonal.

Try it yourself​

These exercises are left without solution.

  1. Implement the task assignment with the framework of the course: a class that extends Node with the heuristic described above and the initial limit given by the diagonals. Check that it reproduces the trace and the optimum 61. Then try a better initial limit: the cost of the greedy assignment.
  2. 0/1 knapsack. Implement the best-first B&B with the fractional bound. Remember that it is a maximization problem: either mirror the comparisons, or minimize the negative of the value.
  3. 8-puzzle and 15-puzzle. Implement the reachability test, the Manhattan heuristic (without the empty cell) and the priority g+hg + hg+h. Check that the solutions have the minimum number of moves by comparing with breadth-first search on small instances.
  4. Traveling salesman. Design a lower bound for a partial tour. Hint: every city not yet left must still be left once, at least through its cheapest outgoing edge.
  5. Compare. For the N-queens problem, measure the memory used (maximum number of live nodes) by the B&B as nnn grows, and compare it with the depth of the recursion in backtracking.
