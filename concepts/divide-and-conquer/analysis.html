Analyzing Divide and Conquer Algorithms

⏱ 12 min readRead first: The Divide and Conquer Scheme

The loops of iterative algorithms can be analyzed by counting iterations, as we did in the first chapter. Recursive algorithms need a different tool: the execution time is expressed in terms of itself applied to smaller sizes, giving a recurrence equation. Fortunately, most divide and conquer algorithms follow one of two very regular patterns, and for both of them the solution is known in general. This lesson presents those two patterns, explains where their formulas come from, and shows how to apply them.

What you will learn in this lesson
  • How to model a divide and conquer algorithm with the parameters aaa, bbb and kkk.
  • The complexity formulas for division and subtraction schemes, and the intuition behind them (the recursion tree).
  • How to identify aaa, bbb and kkk in real code, and the most common mistakes.
  • The limits of these formulas.

The Parameters aaa, bbb and kkk​

Both schemes are described by three parameters:

  • aaa: the number of subproblems (recursive calls) executed in each invocation;
  • bbb: how the size decreases: each subproblem has size n/bn / bn/b (division) or n−bn - bn−b (subtraction), where bbb is a constant;
  • kkk: the cost of the work done in each invocation excluding the recursive calls (dividing and combining) is O(nk)O(n^k)O(nk), a polynomial.

The base case takes constant time (or, more generally, c⋅nkc \cdot n^kc⋅nk for its small size).

Where does it come from? The recursion tree​

The total time is the sum of all levels: c⋅nkc \cdot n^kc⋅nk multiplied by a geometric series of ratio r=abkr = \frac{a}{b^k}r=bka​. Everything depends on that ratio:

  • a<bka \lt b^ka<bk (r<1r \lt 1r<1): the work decreases from each level to the next. The sum is dominated by the first term: the work at the root, O(nk)O(n^k)O(nk). The subproblems shrink faster than they multiply.
  • a=bka = b^ka=bk (r=1r = 1r=1): every level does the same work, c⋅nkc \cdot n^kc⋅nk, and there are log⁡bn\log_b nlogb​n levels: O(nklog⁡n)O(n^k \log n)O(nklogn).
  • a>bka \gt b^ka>bk (r>1r \gt 1r>1): the work increases from each level to the next. The sum is dominated by the last level, the leaves, whose number is alog⁡bna^{\log_b n}alogb​n. By the logarithm rule xlog⁡by=ylog⁡bxx^{\log_b y} = y^{\log_b x}xlogb​y=ylogb​x from the asymptotic notation lesson, alog⁡bn=nlog⁡baa^{\log_b n} = n^{\log_b a}alogb​n=nlogb​a: O(nlog⁡ba)O(n^{\log_b a})O(nlogb​a).

So the three cases correspond to three situations: the cost is concentrated at the top of the tree, evenly spread over all levels, or concentrated at the bottom.

Subtraction Scheme​

The execution time satisfies:

T(n)={a⋅T(n−b)+c⋅nkif n is greater than the base casec⋅nkin the base caseT(n) = \begin{cases} a \cdot T(n - b) + c \cdot n^k & \text{if } n \text{ is greater than the base case} \\ c \cdot n^k & \text{in the base case} \end{cases}T(n)={a⋅T(n−b)+c⋅nkc⋅nk​if n is greater than the base casein the base case​

and its solution is:

T(n)∈{O(nk+1)if a=1O(an/b)if a>1T(n) \in \begin{cases} O(n^{k+1}) & \text{if } a = 1 \\ O(a^{n / b}) & \text{if } a \gt 1 \end{cases}T(n)∈{O(nk+1)O(an/b)​if a=1if a>1​

(Some textbooks also list a case a<1a \lt 1a<1, but it cannot happen in practice: a recursive algorithm makes at least one call in its general case.)

The intuition is again in the recursion tree, which now has about n/bn / bn/b levels:

  • a=1a = 1a=1: a single chain of n/bn/bn/b calls, with sizes n,n−b,n−2b,…n, n - b, n - 2b, \dotsn,n−b,n−2b,…. The work at each one is at most c⋅nkc \cdot n^kc⋅nk, and there are n/bn/bn/b of them: O(nk+1)O(n^{k+1})O(nk+1). A loop of nnn iterations whose body costs O(nk)O(n^k)O(nk), written recursively.
  • a>1a \gt 1a>1: the number of calls multiplies by aaa at each level, through n/bn/bn/b levels: an/ba^{n/b}an/b calls. The algorithm is exponential, and the non-recursive work does not even matter.
Avoid subtraction with several subproblems

An algorithm with a>1a \gt 1a>1 in a subtraction scheme is exponential, and therefore unusable except for very small inputs. If you find yourself writing two or more recursive calls on n−1n - 1n−1 (or n−2n - 2n−2...), stop and think: most likely the same subproblems are being solved many times, and a different technique (an iterative version, or dynamic programming) is needed.

Identifying aaa, bbb and kkk​

To apply the formulas, look at the code of the recursive method and answer three questions:

  1. How many recursive calls are executed in one invocation (in the general case)? That is aaa. Count the calls that are actually executed, not the ones that are written: in binary search there are two calls in the code, but only one of them runs in each invocation, so a=1a = 1a=1. And a call inside a loop that runs mmm times counts mmm times.
  2. What is the size of each recursive call? If it is n/bn/bn/b, the scheme is division; if it is n−bn - bn−b, subtraction.
  3. What is the cost of everything else (loops, copies, partitions, merges)? If it is O(nk)O(n^k)O(nk), that gives kkk. A constant amount of work means k=0k = 0k=0.

For example, in Mergesort:

public void mergesort(int[] v, int left, int right) {
    if (left < right) {                       // base case: one element, constant time
        int center = (left + right) / 2;      // O(1)
        mergesort(v, left, center);           // call 1, on half the elements
        mergesort(v, center + 1, right);      // call 2, on the other half
        merge(v, left, center, right);        // O(n): goes through the n elements once
    }
}

Two calls are executed (a=2a = 2a=2), each one on half of the elements (b=2b = 2b=2, division), and the rest of the work is dominated by the linear merge (k=1k = 1k=1). Since a=2=bk=21a = 2 = b^k = 2^1a=2=bk=21, Mergesort is O(nlog⁡n)O(n \log n)O(nlogn).

Replacing n−2n - 2n−2 by n−1n - 1n−1 can only make the tree larger, so the scheme with a=2a = 2a=2, b=1b = 1b=1 gives an upper bound, O(2n)O(2^n)O(2n). Notice how Quicksort appears in both tables: with perfectly balanced partitions, it follows a division scheme (a=2a = 2a=2, b=2b = 2b=2, k=1k = 1k=1); with the most unbalanced ones, a subtraction scheme in which one of the two parts is empty, so only one non-trivial call remains (a=1a = 1a=1, b=1b = 1b=1, k=1k = 1k=1). 🧠 Checkpoint: Analyze these schemes

Question: Give the complexity of (1) an algorithm that splits a problem of size nnn into 8 subproblems of size n/2n/2n/2 and combines them in O(n2)O(n^2)O(n2), and (2) the same with 7 subproblems.

Answer: (1) a=8a = 8a=8, b=2b = 2b=2, k=2k = 2k=2: a=8>bk=4a = 8 \gt b^k = 4a=8>bk=4, so O(nlog⁡28)=O(n3)O(n^{\log_2 8}) = O(n^3)O(nlog2​8)=O(n3). This is the divide and conquer multiplication of n×nn \times nn×n matrices with 8 products of half-size blocks: no better than the classic algorithm. (2) With a=7a = 7a=7: O(nlog⁡27)≈O(n2.81)O(n^{\log_2 7}) \approx O(n^{2.81})O(nlog2​7)≈O(n2.81). This is Strassen's algorithm (Strassen, 1969), which saves one block multiplication at the cost of more additions, and beats the classic cubic algorithm for large matrices. The same trick, saving one recursive call, makes Karatsuba's multiplication faster.

How Each Parameter Affects the Cost​

The formulas give useful design guidance:

  • Reducing aaa (fewer subproblems) is often the key to a faster algorithm when a>bka \gt b^ka>bk: Karatsuba (4 to 3 products) and Strassen (8 to 7) are famous examples.
  • Reducing kkk (cheaper division and combination) helps when a≤bka \le b^ka≤bk. For example, Mergesort with an O(n2)O(n^2)O(n2) merge would be O(n2)O(n^2)O(n2) instead of O(nlog⁡n)O(n \log n)O(nlogn).
  • Division beats subtraction: dividing the size by 2 instead of subtracting 1 turns O(n)O(n)O(n) levels into O(log⁡n)O(\log n)O(logn), and can turn an exponential algorithm into a polynomial one.

Limits of the Formulas​

These formulas cover the most common cases, but not all of them:

  • Subproblems of different sizes. If an algorithm divides into parts of sizes n/3n/3n/3 and 2n/32n/32n/3, or into parts whose size depends on the data (Quicksort with random pivots, Quickselect), the formulas do not apply directly. The recursion tree, or probabilistic analysis, is needed. For example, Quicksort's average case is O(nlog⁡n)O(n \log n)O(nlogn), and Quickselect's average case is O(n)O(n)O(n), although neither follows exactly any of the two schemes.
  • Non-polynomial non-recursive work. If dividing and combining costs, for example, O(nlog⁡n)O(n \log n)O(nlogn), kkk is not an integer power. The recurrence T(n)=2T(n/2)+nlog⁡nT(n) = 2T(n/2) + n \log nT(n)=2T(n/2)+nlogn has solution O(nlog⁡2n)O(n \log^2 n)O(nlog2n), which the simple formulas do not give. The general master theorem covers many of these cases.
  • Exact constants. The formulas give the order of growth, not the exact time.

When an algorithm does not fit the schemes, the safest method is to draw the recursion tree, compute the work at each level and add it up, as we did above.

Predicting Execution Times​

Once the complexity is known, the techniques of the first chapter apply directly. For example, if Mergesort (O(nlog⁡n)O(n \log n)O(nlogn)) takes 2 seconds for n=220n = 2^{20}n=220, for n=222n = 2^{22}n=222 it will take about

t2=222⋅22220⋅20⋅2≈8.8 secondst_2 = \frac{2^{22} \cdot 22}{2^{20} \cdot 20} \cdot 2 \approx 8.8 \text{ seconds}t2​=220⋅20222⋅22​⋅2≈8.8 seconds

And if the Towers of Hanoi (O(2n)O(2^n)O(2n)) take 1 second for 20 discs, then 30 discs will take about 210=1,0242^{10} = 1{,}024210=1,024 seconds (17 minutes), and 64 discs, about 2442^{44}244 seconds: more than 500,000 years.

Common mistakes
  • Counting the recursive calls written instead of those executed. Binary search writes two calls but executes one: a=1a = 1a=1.
  • Taking kkk from the recursive calls. kkk is the cost of the non-recursive work (dividing and combining), O(nk)O(n^k)O(nk).
  • Applying the division formulas to a subtraction scheme. First decide whether the size is divided (n/bn/bn/b) or reduced (n−bn - bn−b).

Summary​

  • Divide and conquer algorithms are analyzed with recurrences, characterised by aaa (number of subproblems), bbb (how the size decreases) and kkk (cost of dividing and combining, O(nk)O(n^k)O(nk)).
  • Division (n/bn/bn/b): O(nk)O(n^k)O(nk) if a<bka \lt b^ka<bk; O(nklog⁡n)O(n^k \log n)O(nklogn) if a=bka = b^ka=bk; O(nlog⁡ba)O(n^{\log_b a})O(nlogb​a) if a>bka \gt b^ka>bk.
  • Subtraction (n−bn - bn−b): O(nk+1)O(n^{k+1})O(nk+1) if a=1a = 1a=1; O(an/b)O(a^{n/b})O(an/b), exponential, if a>1a \gt 1a>1.
  • The recursion tree explains the formulas: the cost is concentrated at the top, evenly spread, or concentrated at the leaves.
  • Count the recursive calls that are executed, not the ones written. Subproblems of unequal or data-dependent size need a specific analysis.
