Exercises: Brute Force

These exercises review the lesson on brute force and exhaustive search. Most of them ask the same two questions: how many candidates does brute force examine, and is that feasible? Try each one before reading its solution: the solutions are grouped at the end of the page.

3.1. Pairs that cancel. Given an array of nnn distinct integers, count the pairs of positions i<ji \lt ji<j such that a[i]+a[j]=0a[i] + a[j] = 0a[i]+a[j]=0. Write the brute-force algorithm and give its complexity. Then describe two faster algorithms, one using sorting and one using a hash set.

3.2. Subset sum. Is there a subset of 3 34 4 12 5 2 whose elements add up to 9? Solve it by exhaustive search: how many subsets are examined, and which ones are solutions? If a computer examines 10810^8108 subsets per second, how long would the same search take with 40 numbers?

3.3. Guessing a password. An attacker tries every password of 8 characters at a rate of 10910^9109 attempts per second. How long does the exhaustive search take in the worst case if the password uses (a) only lowercase letters (26 symbols), and (b) lowercase letters, uppercase letters and digits (62 symbols)? How much does each extra character multiply the time in case (b)?

3.4. The closest pair of points. The brute-force algorithm for the closest pair of nnn points in the plane computes the distance between every pair and keeps the smallest. How many distances does it compute? If a computer computes 10810^8108 distances per second, what is the largest nnn it can handle in one second?

Solution to 3.4 ↓

3.5. Magic squares by brute force. A 3×33 \times 33×3 magic square contains the numbers 1 to 9, and every row, column and diagonal adds up to the same value. How many ways are there to fill the table with the nine numbers? Only 8 of them are magic: what fraction of the candidates does brute force examine in vain? What is the magic sum, and why?

Solutions​

3.1. Brute force tries every pair:

int count = 0;
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (a[i] + a[j] == 0) count++;

It performs n(n−1)2\frac{n(n-1)}{2}2n(n−1)​ checks: O(n2)O(n^2)O(n2). Two faster options:

  • Sorting, O(nlog⁡n)O(n \log n)O(nlogn): sort the array and move two indices from both ends towards the center. If the sum is positive, move the right index left; if negative, move the left index right; if zero, count it and move both.
  • Hash set, O(n)O(n)O(n) on average: for each element xxx, check whether −x-x−x is already in the set, then add xxx.

Brute force remains the best tool to test the two faster versions on small random arrays.

3.5. There are 9 positions for the number 1, 8 for the 2, and so on: 9!=362,8809! = 362{,}8809!=362,880 fillings. Only 8 are magic (they are rotations and reflections of a single square), so brute force examines 362,872362{,}872362,872 candidates in vain: all but 1 in every 45,36045{,}36045,360. The magic sum is 15: the three rows contain all the numbers, which add up to 1+2+⋯+9=451 + 2 + \dots + 9 = 451+2+⋯+9=45, so each row adds up to 45/3=1545 / 3 = 1545/3=15. The backtracking version of this search prunes a partial filling as soon as a row cannot add up to 15, and examines far fewer nodes.
