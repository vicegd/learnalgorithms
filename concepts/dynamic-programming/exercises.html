Exercises: Dynamic Programming

These exercises review the two lessons on dynamic programming. For each problem, follow the design steps of the first lesson: define the subproblems, write the recurrence with its base cases, decide the order in which to fill the table, and, when needed, recover the solution from the table. Try each one before reading its solution: the solutions are grouped at the end of the page.

6.6. Keep two values while scanning: the best sum that includes the current element and the best that excludes it. For each element xxx: the new "include" is the old "exclude" plus xxx, and the new "exclude" is the maximum of the old two.

int include = 0, exclude = 0;
for (int x : a) {
    int newInclude = exclude + x;
    exclude = Math.max(include, exclude);
    include = newInclude;
}
return Math.max(include, exclude);

The answer is 41, choosing 7+30+47 + 30 + 47+30+4. Note that greedily taking the largest element first (30) and then the largest allowed ones also gives 41 here, but fails in general: in 5 6 5 it takes 6, while the optimum is 5+5=105 + 5 = 105+5=10.

6.8.

  • (a) Yes. If the shortest path from uuu to vvv passes through www, its part from uuu to www must be a shortest path from uuu to www; otherwise, replacing it by a shorter one would shorten the whole path. This is what Floyd's and Dijkstra's algorithms exploit.
  • (b) No. The longest simple path from uuu to vvv through www need not be made of longest simple paths from uuu to www and from www to vvv: those two paths may share nodes, and joining them would not be a simple path. The dynamic programming lesson discusses this example.
  • (c) Yes, if the subproblems include the number of edges allowed: the best path from uuu to vvv with at most kkk edges is made of a best path from uuu to some www with at most k−1k - 1k−1 edges plus the edge from www to vvv. Adding the right parameter to the subproblem is often what makes the principle hold.

6.9. The subproblems are the values (n′k′)\binom{n'}{k'}(k′n′​) reached from (3015)\binom{30}{15}(1530​): those with k′≤15k' \le 15k′≤15 and n′−k′≤15n' - k' \le 15n′−k′≤15, which are at most 16×16=25616 \times 16 = 25616×16=256. With memoization, the body of the method executed exactly 255 times in our run, once per distinct subproblem reached; every other call returns a stored value immediately. Over a million times fewer than the 310 million calls of the plain recursion.

6.10. Each row of the LCS table depends only on the previous row. Keeping two arrays of length min⁡(m,n)+1\min(m, n) + 1min(m,n)+1 (putting the shorter string along the columns), and swapping them after each row, computes the length with O(min⁡(m,n))O(\min(m, n))O(min(m,n)) memory and the same O(mn)O(mn)O(mn) time. What is lost is the ability to recover the subsequence by walking back through the table, because the earlier rows have been overwritten. (Hirschberg's algorithm recovers it in linear space by combining this idea with divide and conquer.)
