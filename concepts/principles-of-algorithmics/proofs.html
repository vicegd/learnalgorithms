Proofs: Principles of Algorithmics

This page collects the proofs behind the claims of the chapter. The lessons state the results and use them; here they are justified. Each section is self-contained, and the lessons link to the section they need. The proof techniques (induction and loop invariants) are explained in Induction, Correctness and Recurrences.

The linear maximum pairwise product is correct​

The optimal linear solution scans the numbers once, keeping max1 and max2.

Claim. For non-negative numbers a0,…,an−1a_0, \dots, a_{n-1}a0​,…,an−1​ with n≥2n \ge 2n≥2, the method returns the maximum product of two elements at different positions.

Loop invariant. After processing the first iii elements (i≥2i \ge 2i≥2), max1 is the largest of them and max2 is the largest of the remaining ones, that is, the second largest counting repetitions (if the maximum appears twice, max2 equals max1).

Initialization. Both variables start at −1-1−1, smaller than any element. After the first element a0a_0a0​, max1 =a0= a_0=a0​ and max2 =−1= -1=−1 (there is no second element yet). After the second, one of the two cases of the loop places the larger in max1 and the smaller in max2. The invariant holds for i=2i = 2i=2.

Maintenance. Let the next element be xxx.

  • If x>x \gtx> max1, then xxx is the new maximum, and the old maximum becomes the largest of the rest: the code assigns exactly max2 = max1; max1 = x.
  • If x≤x \lex≤ max1 but x>x \gtx> max2, the maximum does not change and xxx is the new second largest: max2 = x.
  • Otherwise, xxx is not larger than either, and nothing changes.

The strict comparison in the first case matters: when xxx equals max1, it goes to the second case and becomes max2, which is correct, because the two equal values occupy different positions.

Termination. After the nnn elements, max1 and max2 are the two largest values (counting repetitions). Since all values are non-negative, any product aiaja_i a_jai​aj​ with i≠ji \ne ji=j has one factor at most max1 and the other at most max2, so aiaj≤a_i a_j \leai​aj​≤ max1 ⋅\cdot⋅ max2, and this product is achieved. ■\blacksquare■

Optimality. Any correct algorithm must read every element: if an element were never read, changing it to a huge value would change the answer without the algorithm noticing. So no algorithm can be faster than Ω(n)\Omega(n)Ω(n), and this one is optimal.

The average case of sequential search​

Claim. If the value is in the array and is equally likely to be at any of the nnn positions, sequential search makes n+12\frac{n+1}{2}2n+1​ comparisons on average.

Binary search is correct​

Claim. If list is sorted in ascending order, the binary search of the lesson returns true if and only if value is in list.

Loop invariant. If value is in list, then it is in the interval list[left..right].

Initialization. At the start the interval is the whole array.

Maintenance. Let k be the central position. If list[k] == value, the method returns true, which is correct. If value > list[k], then, since the array is sorted, every element in list[left..k] is at most list[k], hence smaller than value; if value is in the interval, it must be in list[k+1..right], which is the new interval after left = k + 1. The case value < list[k] is symmetric.

Termination. Each iteration either returns or makes the interval strictly smaller (it removes at least position k), so the loop ends. If it ends because left > right, the interval is empty, and by the invariant value is not in the array: returning false is correct. ■\blacksquare■

Binary search needs a logarithmic number of iterations​

Claim. On an array of n≥1n \ge 1n≥1 elements, binary search performs at most ⌊log⁡2n⌋+1\lfloor \log_2 n \rfloor + 1⌊log2​n⌋+1 iterations.

Proof. Let mmm be the size of the interval at the start of an iteration. The central position splits the other m−1m - 1m−1 elements into two parts of sizes ⌊(m−1)/2⌋\lfloor (m-1)/2 \rfloor⌊(m−1)/2⌋ and ⌈(m−1)/2⌉\lceil (m-1)/2 \rceil⌈(m−1)/2⌉, and the next interval is one of them, so its size is at most ⌊m/2⌋\lfloor m/2 \rfloor⌊m/2⌋. Starting from nnn, after ttt iterations the size is at most ⌊n/2t⌋\lfloor n / 2^t \rfloor⌊n/2t⌋. The loop can only continue while the size is at least 1, that is, while 2t≤n2^t \le n2t≤n, or t≤log⁡2nt \le \log_2 nt≤log2​n. So the number of iterations is at most ⌊log⁡2n⌋+1\lfloor \log_2 n \rfloor + 1⌊log2​n⌋+1. ■\blacksquare■

For n=106n = 10^6n=106 that is 20 iterations, and for n=109n = 10^9n=109, 30. And no algorithm that only compares elements can do better in the worst case: each comparison with an element has at most three outcomes, so with ttt comparisons at most 3t3^t3t different answers can be told apart, and n+1n + 1n+1 answers are possible (each position, or "not present"). Hence t≥log⁡3(n+1)t \ge \log_3 (n + 1)t≥log3​(n+1), which is also Ω(log⁡n)\Omega(\log n)Ω(logn).
