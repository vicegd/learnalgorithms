Summary: Principles of Algorithmics

Everything on one page, to review the chapter before moving on. Each section links to the lesson where it is explained.

Key ideas​

  • An algorithm solves a problem for all its instances, defined by a precondition and a postcondition. It must be finite, definite and effective (Algorithmic Thinking).
  • We judge algorithms mainly by their efficiency in time and memory, and above all by how their cost grows with the size of the input (Measuring Efficiency).
  • T(n)T(n)T(n) is obtained by counting elementary operations; when the cost depends on the data, we distinguish the best, worst and average cases (Complexity Analysis).
  • Asymptotic notation keeps only the growth rate: OOO is an upper bound, Ω\OmegaΩ a lower bound and Θ\ThetaΘ an exact order (Asymptotic Notation).
  • Implementation, language and hardware change only the constant, never the complexity (principle of invariance) (Growth Rates).
  • Data structures and algorithms are designed together: the same algorithm can be fast or slow depending on how the data is organized (Data Structures).

Polynomial classes are considered tractable; exponential ones are not. For exponential algorithms, faster hardware only adds a constant to the size that can be solved.
